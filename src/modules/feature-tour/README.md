# 版本功能演示

此模块负责版本介绍目录、离线演示素材、弹窗播放和本地已读记录，与更新下载模块分开维护。

## 目录

每个版本保留自己的完整内容，不覆盖或删除以前发布的介绍：

```text
feature-tour/
  FeatureTour.tsx
  featureTourCatalog.ts
  featureTourService.ts
  versions/
    0.1.32/
      index.ts
      block-resize.gif
      block-resize.png
      ...
```

`index.ts` 默认导出 `FeatureTourRelease`。`version` 必须与目录名完全一致，`id` 是这套内容的稳定标识，`enabled` 控制是否提供这套介绍，`slides` 按数组顺序展示。每项包含标题、说明、快捷操作提示、GIF、静态封面和替代文字。素材通过本地导入随应用打包，可离线播放。

如果功能适合用静态界面示意，不需要制作动画时可以让 `animation` 和 `poster` 引用同一个本地 SVG 或 PNG。弹窗会自动隐藏播放按钮，并把它作为离线静态功能卡片展示；不要为了满足字段要求生成没有实际内容的占位 GIF。

## 有演示的版本

1. 在 `versions/<版本号>/` 新建目录并放入该版本的素材和 `index.ts`，不要修改旧版本内容。
2. 设置准确的 `version`、稳定的 `id` 和 `enabled: true`，填写至少一项有效 `slides`。
3. 目录使用**目标发布版本**，发布后的 `package.json` 版本须与它完全匹配。`scripts/release.mjs` 会递增版本并同步五个版本文件；例如发布前为 `0.1.32`、本次发布 patch 时，新介绍应放在 `versions/0.1.33/`。目录通过 Vite 自动发现，无需手工维护注册列表。

现有 `scripts/generate-feature-guides.py` 仅用于重新生成 **0.1.32** 的四套演示，输出路径固定在这个版本目录。以后版本应使用对应的素材或单独生成脚本，不能通过升级应用版本使旧生成器覆盖新版本内容。

当前 `0.1.36` 介绍覆盖排列页继续上传、拖拽替换、标尺方向与尺寸编辑、备注图片和样式、SVG 图层归类、生成前分组确认、解析后本地优先并后台上传共享文件、保存确认和审核拼版读取优化。

## 没有演示的版本

不创建目标发布版本对应的 `index.ts` 即可。已创建但暂不启用时设置 `enabled: false`。空介绍、无效介绍、目录名与版本不一致也不会注册。发布脚本不会自动复制上一版介绍；目标版本没有对应目录就不自动展示。

自动展示必须同时满足：当前应用版本有完全匹配的已启用介绍、至少一项有效内容、本地尚未关闭过该版本这套介绍、应用已准备好展示。不会因为存在历史介绍而在无演示的新版本中自动弹出旧内容。

## 历史与已读

用户可从“新功能介绍”菜单主动查看保留的历史版本；主动查看不受已读限制。关闭、跳过或完成会记录对应版本和内容标识。遮罩点击不会关闭弹窗，也不会产生已读记录。

本地键 `printflow-feature-tour-seen` 以 `{ schema: 2, seen: { "版本": "内容标识" } }` 保存各版本已读状态，并兼容此前单条 `{ version, guideId }` 格式。没有对应介绍的版本不会凭空写入记录。
