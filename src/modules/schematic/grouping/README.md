# 图片产品分组

本目录只负责上传页的产品分组引导；不修改 SVG 拆分、排列页布局或导出。

## 交互和保存

- 已有产品的名称或 ID 包含 `standees`，且当前可见的“立牌数量”选项大于 1 时开始引导。隐藏、父级条件不满足或无效的选项不会触发。
- 选择自定义“摇摇乐”“照片夹”，以及同类英文名称时也进入引导。
- 自定义名称、已保存自定义产品预设和切换到“自定义”标签都会重新检查触发条件；预设本身已是“摇摇乐 / 照片夹”时不需要再改一次名称。若自动触发被取消，也可在属性区点击“开始分组引导”。
- 属性区始终提供“自由组合图片”入口。它不检查产品名称、立牌数量或已确认状态，允许把当前选中的未分组图片主动合成一个自由图片组；组内每张图的产品、尺寸、工艺、QT 和备注都可独立编辑。自由组保存 `productGroupMode: "free"`，重新打开后仍保持自由编辑，不会套用产品组的产品/立牌数量锁定。
- 初始选中的图片进入组。点击暗色卡片加入成员，点击组内缩略图切换当前编辑图片。缩略图的大图预览按钮仍只预览。
- 引导期间，“已选产品”的列表项与状态标签显示红色，卡片点击和复选框不能再选择它；批量选择触发引导时也跳过已确认图片。当前组内已经确认的成员仍可从引导缩略图切换编辑或移除。普通状态下保持属性编辑与蓝色标签，红色提示不修改持久化组颜色。
- 组内缩略图右上角的删除图标将图片移出当前组，清空产品、规格、QT、配件及其图片、确认状态和组颜色，保留原图及独立备注。通过 Rust 更新当前历史批次，成功后才移除；失败保留原状态并允许重试。移除主图时由剩余首图接任，移除当前图时切换到相邻成员，移除最后一张时退出引导并取消选择。
- 后加入的图片只锁定产品和立牌数量。工艺、尺寸、印刷选项、配件、QT、备注等独立编辑。工艺切换到另一个数量字段时，自动填写同一件数，清除旧分支的数量及图片；父级暂时清空时保留主图的原始数量，避免将固定件数清空。确认时只将数量作为分组约束保留，其余选项仍按当前图片自己的显隐规则校验。
- 引导中的 **确认 / 保存批次**：一次提交全组每张图片各自的完整草稿，同步产品名称、产品 ID、立牌数量及分组信息。Rust 保存成功后，全组卡片状态和缩略图状态一起更新为已确认 / 已保存。工艺、尺寸、印刷选项、配件、QT、备注仍是每张图自己的值，不将当前图的属性整份复制给其他成员。
- **确认**：执行全组保存，成功后自动退出引导；保存失败保留引导和全部草稿。**保存批次**仍在保存后继续引导。不会将未提交草稿留在内存而让界面看起来已经保存。只有一张图片也可以确认，但不会形成产品组。
- **退出引导 / 取消选择**：不执行保存，退出引导并清空选择；保留已经保存的产品组与属性，放弃尚未保存的本次修改。两个入口均在保存进行中禁用。
- 同步立牌数量时，按每张图**本次提交的工艺草稿**映射件数，清除旧数量键和对应图片。首次加入且产品不同的图片以主图属性初始化，原有 QT、备注保持独立，已有同产品属性不会被整份覆盖。
- 保存失败会保留引导和草稿，显示错误，允许重试。保存期间禁用重复操作。
- 普通点击已分组卡片只选择图片、回填属性，不自动启动引导。右侧显示 **编辑产品组** 按钮，点击后才恢复全组引导，并以所点图片作为当前编辑图。普通选择时可以单独确认工艺、尺寸、QT、备注等独立字段；产品和立牌数量锁定，需要进入组内修改。
- 新引导不招募已经属于其他组的成员，即使旧数据里该成员的确认状态为空。恢复已有组允许载入已确认成员，继续禁止把其他已确认图片加入新组。
- 主图 ID 随资产保存，避免列表顺序变化后主图身份错位；再次打开历史批次保留每张图的独立属性、原主图、编号及颜色。旧批次没有主图 ID 时，优先选择有有效分组产品信息的成员作为主图。
- 兼容历史错误数据：若同组有已确认的有效产品主图，而其他成员只有组号和颜色、产品为空，打开批次时在内存补齐这些成员的产品、属性、主图 ID 和确认状态，保留各自 QT、备注。已有有效产品的成员不覆盖独立属性，没有有效主图则不猜测产品。下一次保存更新原批次 ID，打开操作本身不写数据库。

## 模块边界

图片列表使用 `productGroupOrdering.ts` 将产品组按原批次中首次出现顺序（也就是标签编号顺序）放到最前面，组内顺序保持稳定，未分组图片按原顺序排在后面。分类筛选在完整排序后执行，列表、引导缩略图、右侧选中序号使用同一顺序，图片池弹窗复用该排序。

自定义产品名包含 `Photocard Holders` 或 `Shaker` 时，使用同一套产品分组引导，并在组内前四个位置显示固定槽位 `Example`、`Front`、`inside`、`Back`。缩略图支持拖动换位，第四张之后仍可继续加入图片；拖动后的顺序写入每张资产的 `productGroupPosition`，历史记录和排列页按该顺序恢复。其它产品继续使用普通分组引导。自由组合与产品专用入口在属性面板合并为一个按钮，产品名能识别时进入专用引导，否则进入不受产品限制的自由组合。

合并后的手动入口不会因为图片已经是“已选产品”而失效：只要图片还没有 `productGroupId`，点击入口就可以建立新组；自动触发仍然只对未确认图片启动，避免编辑既有属性时误进入引导。

`UploadImageGrid.tsx` 负责上传列表的按行网格，已取消瀑布流。每个产品组独立分区，组内保持选择顺序；同一行卡片等高，下一行整体开始。小窗口两列、中等窗口三列、大窗口四列，滚动限于列表内部。产品名下显示资产 sourceGroupWidthMm/sourceGroupHeightMm，保留三位小数，缺少实测值显示未记录，不以页面像素冒充真实尺寸。

`productGrouping.ts` 负责触发条件、共享字段同步、草稿继承和全组提交；`productGroupRestore.ts` 负责手动恢复组、普通卡片属性确认以及旧数据兼容；`productGroupRemoval.ts` 负责移除成员、清空产品属性和主图接替；`useProductGrouping.ts` 负责引导会话、成员切换、取消和异步保存；`ProductGroupGuide.tsx` 与样式文件负责提示和缩略图。

`SchematicPage` 注入当前批次的保存函数，调用原有 Rust `save_batch`。前端不另建历史记录，也不使用浏览器存储。继续使用当前批次 ID 更新原记录。

## 持久化字段

每张 `Asset` 使用可选 `productGroupId`、`productGroupColor`、`productGroupLeaderId` 和固定槽位需要的 `productGroupPosition`。同组图片使用相同组身份和颜色，颜色创建时确定一次。Rust 对应 `product_group_id`、`product_group_color`、`product_group_leader_id`、`product_group_position`，通过 camelCase Serde 写入现有批次资产 JSON，并参与批次签名；旧数据缺少这些字段时默认为空或零，不需要数据库表迁移。移除主图时同步新的主图 ID，解组时清空组身份和槽位。

属性仍存于每张资产的 `productId`、`productName`、`attributes`、`attributeImages`、`note`、`noteImage` 和 `attributesConfirmed`。自定义产品的本地预设 ID 在保存时同步给组内草稿，但不复制成员的尺寸、QT 或备注。

## 验证

`node --test tests/product-group*.test.mjs` 覆盖触发与显隐、后续成员锁定、确认保存的共享字段同步、独立保存、组恢复、主图身份、自定义属性及移除清理。Rust `note_persistence_tests` 覆盖旧资产默认值和新字段 JSON 往返。

交互回归覆盖：普通点击不进引导、手动进入、直接结束保存全组、保存批次提交全部草稿、状态同步、取消选择和退出不写入、失败重试、重新打开历史回显，以及小窗口内部滚动。

2026-09-17 使用 `Lapitalii Klein马口铁` 历史批次的真实元数据与本地产品配置做只读验证：原组 3 个成员中 2 个缺产品，补全后 3 个都有产品与确认状态，数据库原始记录未被测试修改。对应最小回归见 `tests/product-group-legacy.test.mjs`。
