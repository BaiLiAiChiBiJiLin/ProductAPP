# 云数据库与共享图片

## 数据归属

| 数据 | 保存位置 | 可见范围 |
| --- | --- | --- |
| 用户、历史批次、产品属性、排序、真实尺寸 | MySQL | 历史批次按用户 ID 隔离 |
| 审核的完整编辑快照、付款状态、生产任务、拼版池 | MySQL | 所有已登记用户 |
| 原始 SVG、背面/图层 SVG、备注图片、导出文件 | SMB 共享目录 | 所有工作电脑具有共享目录权限 |
| 上传解析临时文件、界面偏好、临时拼版导入、自定义产品名称库、产品配置缓存 | 当前电脑 | 当前电脑 |

历史批次右键转移仅在事务中改变所属用户。文件不移动、不复制；公共审核和生产任务不跟随归属改变。接收人刷新历史记录即可看到。首次设置用户名会登记或关联同名用户，本机绑定稳定的用户 ID；修改用户名不会改变数据归属。用户名识别不等同于密码登录，适用于可信内部电脑，不能作为抵抗客户端篡改的安全边界。

审核保存导出时的完整快照，包括所有页面、图片位置/旋转/尺寸、图层和背面图、标注、属性、备注及显示配置。编辑公共审核时，如果源批次不属于当前用户，则恢复为独立编辑内容，不能覆盖他人的私有批次。之后显式保存批次会创建自己的新批次。

## 配置

开发或本机覆盖配置：将 `config/printflow-config.example.toml` 复制为软件目录下 `printflow-data/config.toml`。开发项目对应 `D:\project\productionAPP\printflow-data\config.toml`；安装包对应可执行文件旁的目录。此实际配置被 Git 忽略，禁止提交密码或打包到安装器。

1. 填写对应环境的数据库账号、密码、端口。生产库为 `print_flow`，当前开发库为 `print_dev`（开发库名必须以 `_dev` 结尾）。
2. 设置 RDS 网络白名单，确认工作电脑可以连接外网地址；内网地址只适用于能路由到 RDS VPC 的电脑。启用 RDS SSL/TLS；如使用私有 CA，将控制台下载的 CA 证书地址填入 `ca_certificate`。客户端验证证书及主机名，不允许关闭校验。
3. 确认所有电脑都能读、写、删除对应 SMB 目录。生产路径为 `\\192.168.0.66\电商文件\printFlow\production\SVGhistory`，开发为 `\\192.168.0.66\电商文件\printFlow\dev\SVGhistory`。
4. 将 `mode` 从 `local` 改为 `shared`，重启软件。开发构建拒绝生产目录和不以 `_dev` 结尾的数据库名。
5. 填写用户名，在设置中点击“检查连接与目录权限”。这会连接数据库并创建、校验、删除一个很小的测试文件，不修改业务数据。

正式版没有本机配置时，读取 `\\192.168.0.66\电商文件\printFlow\production\config.toml`；证书放在同目录，配置中使用所有员工电脑都能访问的 UNC 证书路径。统一配置仅包含生产环境，密码不进入源码或安装包，请由管理员限制该目录的读取和修改权限。正式版无法读取配置时阻止业务加载，不回退到本地。已有本机配置优先，需要管理员移除旧覆盖配置或将其改为共享模式。

开发版缺少配置或本机明确配置 `mode = "local"` 时继续原有 SQLite/本地文件流程。首次进入云端模式时，即使本机已有旧用户名，也需确认保存用户名；登记成功才加载业务页面，之后启动无需重复确认。开发与生产登记状态分开保存。共享模式下数据库或共享目录失败会明确报错，绝不会自动切回本地保存。修改配置必须重启；配置和连接池在进程内固定，避免运行中切换到错库。

表定义在 `src-tauri/src/cloud/schema.sql`，首次连接自动建表，数据库本身需先创建。首次初始化账号需要对应数据库的 CREATE、SELECT、INSERT、UPDATE、DELETE 权限；结构版本 1 转换为版本 2 时另需 ALTER 和 DROP 权限（仅作用于当前业务库）；只使用单独业务数据库的受限账号，不使用 RDS 管理员账号。数据库连接默认上限为每客户端 4 个。页面快照放 JSON 列，图片正文放共享文件；建议确认实例的 `max_allowed_packet` 能覆盖大型批次元数据（例如 64 MiB）。

## 数字编号

自定义产品的查询、新增、保存始终走本机 SQLite，即使启用共享模式也不读取云端产品库。结构版本 3 会删除旧的 `pf_custom_products` 表；已有批次、审核和生产快照中的产品名称、产品编号、属性及备注图片继续保留。

结构版本为 3。八张表均使用数字主键，其中七张业务表的 `id` 为 `BIGINT UNSIGNED AUTO_INCREMENT`；`pf_schema` 保留固定数字主键 1。用户归属、生产任务来源审核、文件引用、转移双方及迁移目标均使用数字关联编号。

`pf_records.record_key` 是上传/导出时使用的业务识别标记，快照内部的图片、组、页面及记录引用继续使用这些标记。`pf_resources.hash` 用于文件去重和完整性校验，`pf_requests.request_key` 用于重复请求识别，`pf_migrations.installation_key/local_key` 用于识别旧数据来源；这些字段不再作为数据库主键。

首次连接旧结构时，软件在写入锁内创建新表、转换编号并核对行数，然后一次性切换八张表，并移除旧的云端自定义产品表。共享图片文件及快照内容保留。已删除的批次或迁移目标在历史表中保留来源标记，数字关联置空。升级后需重新确认用户名，按已有用户名关联新的数字用户编号。

## 文件和并发保存

首次上传解析成功后，共享模式自动保存批次，目录为 `源文件名_yyyyMMddHHmmss_批次标识`。同一批次后续更新继续使用原目录。原 SVG 按字节保存，不重压缩其中的 image 数据，也不改变真实尺寸。

文件使用内容校验值命名并复用相同内容；每批有逻辑目录，但相同图片可能引用另一个批次目录中的同一文件。不要手动删除、移动或覆盖单个批次目录。数据库使用相对路径，软件根据配置拼接 UNC 地址。更换整个共享根目录需停用所有客户端，将完整目录复制过去并统一修改配置；只改路径不会搬迁已有文件。

保存先写临时文件、同步、校验，然后发布文件并提交 MySQL 事务。数据库版本号防止旧页面覆盖其他电脑的更改；写请求带唯一 ID，完全相同的请求重试可重放已提交结果。数据库层的写锁序列化文件发布与清理，忙碌超过等待时限会提示稍后重试。SQL 和 SMB 无法组成分布式事务：失败可能留下未引用文件，但不会让事务成功引用尚未写完的文件。遇到提交结果不明确时先刷新核对；有其他编辑或重新生成的临时快照时，旧版本会被拒绝覆盖。

删除历史批次后，立即清理该批次不再被引用的文件、资源记录及空目录；其他批次、审核或生产任务仍引用的文件保留。删除先提交数据库事务，再清理文件；断网或文件占用会提示清理未完成，可重试删除，或在设置里点击“清理未引用文件”继续处理。其他操作产生的未引用文件至少保留 24 小时，再由设置中的清理功能回收。清理支持重试，也会回收失败上传留下的、超过 24 小时的内容文件和临时文件。不要在迁移期间或有其他旧版客户端直接改写共享目录时清理。

## 迁移本机旧数据

切到共享模式后，在设置中点击“检查本机旧数据”，核对数量，再点击“迁移数据”。迁移全部成功后会删除本机旧记录及软件管理的本地图片文件；如果有任何记录未迁移，保留本机数据并提示修复后重试。也可以在检查结果右侧点击“删除旧数据”，确认后直接删除本机旧记录及其文件。

- 复制本机批次、审核、生产记录以及当前用户的本机拼版池；批次归当前用户，审核和生产记录公开。
- 迁移前保留本地数据库及原文件；逐条事务提交，失败项单独显示，再次运行跳过已成功记录。全部迁移成功后清理本机旧记录和软件管理的本地文件。
- 每台安装有稳定的迁移标识，重写跨记录 ID 和引用，防止不同电脑的旧 ID 相互覆盖；自定义产品名称和属性在业务快照中原样保留，名称库由各台电脑的 `printflow-data/custom-products.sqlite` 管理。
- 云端转移与旧版共享包转移独立。本机数据检查、迁移和删除不读取旧转移状态，也不要求先完成或取消旧任务；旧转移任务及回执记录保留，不由云端迁移处理。已经迁移的记录后续应在共享模式继续操作，再次迁移不是持续同步工具。
- 如果各电脑保存了相同业务的独立副本，迁移不会根据客户名自动合并；应由操作人选择需要迁入的数据来源。
- 备份需要同时备份 MySQL 和完整共享文件目录；只备份数据库无法恢复图片。

## 验证和上线检查

本地自动化集成测试使用仅监听 `127.0.0.1:33317` 的临时 MySQL/MariaDB，创建随机测试库，完成后删除测试库，不访问 RDS。测试代码见 `src-tauri/src/cloud/tests.rs`，显式传入测试密码后运行 `cargo test --lib cloud:: -- --include-ignored`。普通测试默认跳过需要数据库的测试。

上线前仍需在两台实际电脑上使用开发库和开发共享目录验证：A 上传后 B 看不到私有批次；转移后 B 刷新可见、A 不可见；两人均能恢复公共审核及打开生产任务；同时保存旧版本有明确冲突提示；断开数据库/共享目录时不出现本地兜底保存；恢复网络后重试；删除批次不损坏公共审核/生产引用。最后确认生产环境配置与开发环境隔离。

本次验证：前端生产构建通过；云端原生测试 7 项（含本机数据库事务与 TLS）通过，原有审核测试 11 项及生产流转测试 10 项通过（生产测试串行运行，避免旧测试临时目录并发冲突）。前端相关回归通过；全量回归中排列边框的 5 项断言在修改前的 HEAD 副本中也失败，未在此存储改造中调整。真实 RDS 的开发库 `print_dev` 和生产库 `print_flow` 均已通过原生驱动 TLS 验证并初始化业务表（当前结构版本 3，共 8 张）；生产统一配置及 CA 证书已放入共享目录。两台实际工作电脑仍需按上述流程联调，旧本地业务数据未自动迁移。
