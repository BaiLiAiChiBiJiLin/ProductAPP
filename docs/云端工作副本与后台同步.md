# 云端工作副本与后台同步

## 目的

共享模式下，云数据库和共享图片目录仍然保存正式数据；示意图审核和生产拼版的交互过程使用本地内存及本地队列，避免每次编辑、撤销和回退都等待网络、数据库锁或共享文件读取。

## 交互原则

- 打开记录时从云端读取一次，当前页面的编辑、撤销、恢复和排版调整只修改本地工作状态。
- 已保存的批次属性修改会合并到 `cloudSyncQueue`，同一批次只保留最后一次快照。
- 队列写入本地 WebView 存储，软件重启后可以继续同步；网络失败按 2 秒、5 秒、15 秒、30 秒、60 秒递增重试，并加入少量随机错峰（最长 60 秒）。恢复网络、窗口重新获得焦点或恢复显示时，提前唤醒可自动重试的任务。
- 点击保存或确认生成示意图前，先等待同步队列完成，再执行正式云端写入；返回历史列表不等待上传，但保留待上传图片。
- SVG 解析完成后先把图片加入本地工作副本，上传共享文件存储改由同一队列后台执行；队列确认当前版本成功后才清理临时文件，并把共享资源路径回写到当前图片。
- 顶部状态显示“待同步”“正在同步”“同步稍后重试”或“同步待处理”。点击可查看具体批次、失败原因、处理建议、重试倒计时，并单独立即重试该批次。
- 拼版回退先更新当前列表，再后台完成云端状态变更；失败后刷新列表并显示错误。

## 资源读取

审核记录中的 SVG 资源按最多 4 个并发读取，并按记录和资源 ID 缓存当前会话结果，不再逐个串行等待。

生产拼版详情在当前会话缓存已加载的任务；数量更新成功后替换缓存，失败后清除缓存，下一次读取会重新向云端获取。

## 云端一致性

云数据库仍是唯一正式来源，本地队列不是第二份业务数据库。正式写入继续使用共享后端的版本校验；显式保存和进入生产前会先冲刷队列，避免旧快照覆盖最新数据。

### 连续编辑期间的同步回写

- 同一批次有更新的队列版本时，旧请求成功只推进后端保存版本，不向页面发送完成通知，也不清理仍待上传的临时图片。
- 当前队列版本完成时，通知同时携带提交快照和保存结果。页面按图片 ID 匹配，后台同步不按数组位置匹配，避免删除、换图或排序后串到其他图片。
- QT、产品选项等属性以当前本地修改为准；只有产品和属性仍与提交快照一致时，才接收 Rust 自动补齐的工艺等属性。共享图片路径单独回写，且不能覆盖提交后已更换的资源路径。
- 客户名称、绘图日期、发货日期和来源逐字段比对，保留同步期间新填或主动清空的值。
- 属性确认等待存储模式查询后，重新检查当前批次，并合入等待期间已回填的永久资源路径和最新批次信息，避免再次提交已清理的临时文件路径。
- 显式本地保存的重复批次匹配仍可按原顺序对应不同资源 ID，与后台共享同步的回写规则分开处理。

回归检查：`npx vitest run tests/qt-cloud-sync.test.tsx tests/cloud-sync-queue.test.ts tests/cloud-batch-reconciliation.test.ts`。页面测试通过延迟云端回复，验证连续确认多张图片的 QT 后，旧回复不会使已填写的数量消失，也不会回退同步期间修改的批次信息。

### 其他后台请求的旧响应保护

- 过期队列版本的失败不计入新版本，也不给新版本追加重试延迟。显式等待同步会立即尝试待重试任务；仍有未同步项就抛出错误，不能当作保存成功继续执行。启动时仍通过状态提示和自动重试处理网络失败。
- 重新打开历史批次和转移批次前等待同步完成，避免读回旧 QT 或在转移后继续保存。这些同步确认仍是全局等待，失败时保留待同步数据并提示错误。
- 删除批次使用独立协调流程：暂停并持久记录该批次的删除意图，只等待该批次已发出的保存结束，然后执行删除。保存失败（包括源文件缺失）不阻止删除，无关批次的同步也不参与等待；成功后只移除目标批次的待同步任务。
- 删除请求失败时保留快照和临时图片，暂停该快照的自动保存，供用户重试删除。删除可能已在服务器提交但响应丢失，因此软件重启或队列重试也不能自动上传旧快照、重新创建记录。用户重新编辑并提交新的快照时才恢复保存。
- 删除失败的提示不会隐藏历史卡片。删除全部图片与历史卡片删除共用同一服务；删除部分图片等待存储模式返回后，从当前工作副本取剩余图片的最新路径和批次信息，避免把刚刚清理掉的临时路径重新写入队列。
- 返回列表不阻塞，但临时清理会跳过队列中和在途保存仍引用的图片路径。
- 云端版本号不能被迟到的旧读取降低；旧详情也不能与较新版本号一起交给编辑器，否则下一次保存可能绕过原有版本冲突保护。过期详情读取提示重新打开或刷新。
- 拼版回退期间，刷新结果继续隐藏正在回退的任务；完成后使旧刷新失效并重读，失败提示保留。拼版池保存期间发起的旧配置读取不能覆盖新保存的配置。
- 拼版详情的短时缓存从请求完成后开始计时，慢速单张或批量 QT 保存期间，读取复用该保存结果，避免 3 秒到期后读到旧数量。
- 审核资源缓存按记录保存时间隔离，保存或删除成功时失效；本地重新导出复用资源 ID 时不会继续显示旧 SVG。离开审核模块后，未完成的编辑读取不再强制跳回旧工作区。

相关回归覆盖 `cloud-backend`、`cloud-sync-queue`、`batch-sync-lifecycle`、`history-cloud-sync`、`imposition`、`imposition-pools` 和 `schematic-review` 测试。使用可控的延迟响应复现竞态，不依赖真实云端网络时序。

## 失败恢复与请求确认

- 网络、数据库忙碌及无法确定结果的 I/O 错误自动退避重试。真实版本冲突、明确缺失的源文件、无效数据或配置、账号归属问题停止定时重试，保留队列快照和临时文件，显示“同步待处理”。处理原因后可手动重试；不会自动提高版本号来覆盖别人的修改。
- 已标记删除的快照始终暂停保存；同步详情提示回到历史记录重试删除，不能用“立即重试”把旧保存重新上传。
- 批次写请求通过独立的 `cloudWriteJournal` 保存原始参数、请求 ID、基础版本及原始时间戳。日志按环境、配置路径、存储根和账号隔离；收到云端结果后，把确认结果和新的基础版本一起持久化。回复丢失或软件重启后先重放同一请求，确认成功才提交后续编辑。
- 同一记录的写入串行执行，连续重复提交复用在途请求；A→B→A 的修改仍按实际顺序保存。界面只接收当前队列版本的完成通知，旧请求确认不会回退新 QT 或属性。
- 大型审核 SVG 等非批次请求继续使用会话内的请求重试，不把完整 SVG 放入 WebView 的持久化日志；只有轻量版本信息持久化。它们不提供批次队列相同的跨重启自动恢复承诺。
- 本地队列或写请求日志保存失败会明确报错，未持久化的新批次请求不会发送到云端；不能把磁盘/存储配额失败当作已成功排队。损坏的请求日志保留原文并阻止继续写入。
- Rust 幂等摘要基于原始请求参数。重放已提交的新请求时不再读取或重新补齐可能变化的工艺目录；旧版摘要仍按旧规则严格校验。无法恢复旧请求标识的历史遗留冲突需要人工核对，不能推断成功后强制覆盖。

## 后端连接与诊断

- 共享配置只缓存成功结果。首次读取共享目录失败后，下次调用重新读取，不再把首次网络错误缓存到退出软件。
- 连接池等待不持有全局注册互斥锁，池满等待上限为 10 秒；数据库连接超时 10 秒，读写超时 30 秒。SMB 文件调用仍由 Windows 的文件系统超时控制，不能用前端超时另起重复写入来绕过。
- 后端记录操作类型、配置/连接/身份/准备/写入阶段、耗时和成功/失败，不记录参数、用户名、凭据或原始数据库错误。用户可从同步详情取得业务失败原因，结合日志阶段定位。
- 文件发布和 SQL 事务仍由原有全局写锁保护，文件存在性、哈希和路径范围校验继续执行。大批图片仍可能持锁较久；后续拆分上传与短事务必须先设计发布/清理之间的一致性保护，不能直接去掉锁或跳过图片校验。
