# 图片资产原始像素尺寸

上传解析在 `assets.rs` 已有的 usvg 场景树上调用 `asset_images::collect`，不再次解码或渲染图片，不复制图片二进制数据。`Image::size()` 返回 PNG/JPEG 等原始分辨率，而非 SVG 的放置宽高。

每张资产新增 `sourceImages`，随 Rust 的资产 JSON 保存到本地数据库，并随导入事件、历史记录返回前端。每个条目记录 `nodeId`、`format`、`widthPx`、`heightPx`、`widthMm`、`heightMm`；一张 SVG 中有多张位图时分别记录。usvg 会把原始 image ID 移到生成的父组上，采集时结合原 XML 的 image ID 集合恢复关联，避免把产品组 ID 当作图片 ID。

## SVG 内的毫米尺寸

详情中的“图片尺寸（SVG 内）”显示毫米并保留三位小数，像素宽高继续作为原始元数据保存。毫米尺寸代表完整图片在原 SVG 中的放置大小，包含图片自身与父级变换、根 viewBox 和 `preserveAspectRatio` 的映射，不是文件 DPI 推算的尺寸，也不是裁剪/蒙版后的可见范围。

计算使用已有 `image.abs_transform()` 的二维线性分量。原像素宽乘 `hypot(sx, ky)`，原像素高乘 `hypot(kx, sy)`，得到两个变换后边向量的 CSS px 长度，再乘 `25.4 / 96` 转毫米。这里的 96 是 SVG/CSS 单位换算，不是假定 PNG/JPG 的分辨率。旋转不把图片尺寸膨胀成轴对齐包围盒；镜像和非等比缩放分别作用到对应边长。计算在单图 viewBox 调整前的场景树中进行，不修改图片内容。

- 旧记录没有此字段或只有像素宽高：表示尚未记录毫米尺寸，详情提示重新导入，不把原像素按固定 DPI 换算。
- 新记录字段为空数组：解析树未发现位图，不能把矢量 SVG 视口尺寸当作原始像素尺寸。
- `sourceGroupWidthMm`、`sourceGroupHeightMm` 仍然表示原图测量的毫米尺寸，两种尺寸独立保存。
- 不修改 SVG 内容、嵌入图片字节或原有拆分/排列算法。

在图片列表右键点击卡片或缩略图，选择“详情”，查看每张图片的毫米尺寸、整个资产的真实尺寸、来源文件、保存位置、产品属性和备注。此操作不改变选择或产品组合。详情不会展开 SVG/Base64，也不会为旧记录额外解析源图。

验证：`cargo test --example verify_asset_images`；`cargo run --example verify_asset_images -- <SVG路径>` 可测试真实大文件（不写入批次）；`npx vitest run tests/asset-details.test.tsx tests/upload-service.test.ts tests/batch-history.test.ts`。
