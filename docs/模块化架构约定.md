# 模块化架构约定

## 目录边界

业务模块必须独立放在 `src/modules/<模块名>/` 下，只维护本模块的页面、组件、状态、类型和业务逻辑。

当前模块规划：

- `src/modules/order/`：订单模块
- `src/modules/image-edit/`：订单图片编辑
- `src/modules/schematic/`：生成示意图，包括图片上传、图片池、审核弹窗、Konva 画布、分页排版和导出
- `src/modules/imposition/`：生产拼版
- `src/modules/progress/`：生产进度

## 共享目录

- `src/shared/components/`：跨模块通用 UI
- `src/shared/hooks/`：跨模块通用 React hooks
- `src/shared/types/`：跨模块类型
- `src/shared/utils/`：纯函数和格式化工具
- `src-tauri/src/commands/`：按命令领域拆分 Rust command
- `src-tauri/src/services/`：SQLite、SVG 解析、导出等基础服务

## 约束

1. `App.tsx` 只负责路由、模块切换和全局布局，不承载具体业务逻辑。
2. 生成示意图模块内部的状态不得直接依赖其他业务模块的组件状态；跨模块数据通过明确的类型和服务接口传递。
3. Konva 画布、图片池、上传解析、排版分页、导出分别拆成独立组件或 service。
4. UI 文案、模型类型、持久化 DTO 与实现分离，避免修改一个页面影响其他模块。
5. 新功能先归属模块再编码，禁止继续向根目录 `App.tsx` 堆叠代码。
