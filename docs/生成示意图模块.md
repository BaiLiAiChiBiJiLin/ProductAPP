# 生成示意图模块：页面与功能逻辑

## 当前已实现（2026-09-13）

### 产品上传到示意图预览流程

1. 进入生成示意图模块首先显示产品上传页。员工选择产品类型、画布规格和导入方式，再通过 Tauri 系统文件选择器上传素材。
2. SVG / PNG 在 Rust 后台完成解析、拆分、真实预览生成和持久化；同一源文件名再次上传会替换原素材及其旧页面引用，不产生重复图片。
3. 点击“生成示意图”会打开图片池检查弹窗，列出本次图片资源。员工可取消继续上传或确认生成。
4. 确认后按 A4 容量自动排列素材，当前页放满后自动创建下一页，并进入示意图预览页。
5. 示意图预览页隐藏产品上传区，图片池占满右侧空间，使用产品 A / B / C 切换查看对应素材；排版状态继续与画布和缩略图同步。
6. 排列页画布单选图片后，右侧图片池区域自动切换到“图片属性”页签，复用上传页的产品属性编辑器；取消选中、切换页面或选中表头时回到图片池。属性保存后先刷新当前组详情，只有产品或印刷模式改变才重新分页。

上传页左侧显示已解析图片列表，每张图片可单独设置产品属性并标记“不进入示意图”；右侧保留图片上传与解析操作区。被排除图片会以灰色显示，生成时自动跳过。

- 顶部保留五个模块入口；当前仅生成示意图可用，其余点击提示尚未开放。
- 初次使用只有一张空白 A4（210 × 297 mm）页面，没有模拟素材。直接上传会自动创建临时批次；切换页面，缩略图、图片数量和页面状态随排版数据更新。
- 最近使用批次以卡片显示，点击后在图片列表区域显示加载动画再打开；当前批次可用左侧返回图标舍弃临时内容并回到批次列表，未保存临时批次不会进入历史。
- 当前批次点击“保存批次”时按钮显示加载动画；Rust 持久化完成后仍停留在当前图片列表，方便继续检查或进入示意图生成，不自动退出列表。
- 确认生成示意图或手动保存批次时，Rust 会按批次元数据（客户名称、绘图日期、预计发货日期、来源）以及每张图片的名称、产品 ID/名称、属性、尺寸、SVG 内容摘要（FNV-1a + 字节数）、导入模式、合并状态、来源分组和列表顺序生成批次指纹；如果新批次已有相同指纹，则复用原记录的资源，不新增历史批次，也会清理本次导入产生的临时文件。已打开或当前编辑批次始终复用其批次 ID，保存时直接更新原历史记录；因此只修改某一张图片的产品或属性不会产生新的历史卡片。
- 点击确认生成示意图后，确认弹窗的提交按钮立即进入加载状态并禁用，异步保存和分页完成前会阻止重复提交。
- 历史批次卡片提供删除按钮，删除前二次确认；Rust 删除批次记录，并仅清理不再被其他批次引用的持久化 SVG 文件。
- 页面整体固定，页面列表和图片池单独滚动。A4 在中间可用区域按宽高等比适配，不设会遮挡纸张的最小缩放值。
- 产品入口记录素材的 productId。文件选择使用 Tauri 2 dialog 的 open，支持 SVG、PNG；也可将 SVG、PNG、JPG 文件直接拖到上传区域，Tauri 原生拖放事件会把真实文件路径交给 Rust 解析。取消不导入。浏览器预览提示须在桌面应用导入，不再使用 input[type=file] 或只记录文件名的假导入。
- 导入选项：自动判断单图 / 一张内多图（默认，由 Rust 根据 CorelDRAW / Illustrator 标记、印刷辅助线、背景和顶层图形结构决定）；也可手动选择整图或按顶层分组拆分。PNG 始终整图。Rust 会返回实际采用的模式并显示在进度区。
- Rust 后台任务读取 XML 的完整节点，保留 defs、样式、引用、变换及根节点属性；拆分资源只收紧 `viewBox`，不改写根 `width/height`，图片池、画布和导出都继续使用 SVG，不为每个素材额外生成 PNG。usvg 负责场景测量和解析，resvg 仅用于像素校验和最终 PNG 导出。
- SVG 拆分先按含图片节点的渲染包围盒建立图片组，再将独立巡边路径、线条和其它绘制节点按实际包围盒匹配到最近图片组；组内保持原始文档顺序。合并前后由 resvg 做 0.1% RGBA 像素差校验，失败时保留独立资源。
- SVG 尺寸测量统一使用 `examples/measure_groups.rs` 同源的 `svg_measure` 矢量路径算法：从原始图层读取已累乘父级变换的无填充描边路径，用 tight bounds 计算曲线边界，过滤填充、图片外框以及带 clipPath/mask/filter 的外部几何，再按原始根 `width`/`height` 单位换算毫米，误差目标为 0.001 mm。拆分资源只替换根 `viewBox` 为该图层在原始用户坐标中的范围，根 `width`、`height`、defs、变换、裁剪和蒙版保持原样；页面使用资源的 `Asset.width/height` 等比缩放显示，不回写或重采样 SVG 源文件。
- 三种 SVG 导入类型采用独立 Rust 模块，公共层只负责分类、进度和 `Asset` 生成，避免修改一种格式时影响其它格式：`svg_modes/whole.rs` 只保留整图；`svg_modes/top_groups.rs` 将多个无嵌套的根级 `<g>` 作为完整组；`svg_modes/scene.rs` 处理含嵌套图层、图片、路径、裁剪和蒙版的复杂场景；`svg_modes/classifier.rs` 根据根级分组、嵌套层级、`image` 和 `clipPath/mask/filter` 特征选择模式。

### 三种 SVG 类型的独立实现方法

#### 1. 整图型 SVG：`svg_modes/whole.rs`

- **适用特征**：没有足够的有效分组，或自动判断无法确认拆分关系的 SVG。
- **处理方式**：只验证根节点是 `<svg>`，保留原始 XML、根节点尺寸、`viewBox`、`defs`、样式、图片引用和所有图层。
- **拆分规则**：不遍历图层，不计算候选包围盒，不合并路径，也不修改原始坐标。
- **输出方式**：整个 SVG 生成一个 `Asset`，`mergeStatus` 为 `whole`，图片池中显示为一张图片。
- **失败策略**：SVG XML 无效或无法由 usvg 解析时返回导入错误，不尝试使用其它拆分算法。

#### 2. 顶层分组型 SVG：`svg_modes/top_groups.rs`

- **适用特征**：根节点下有两个或以上平级 `<g>`，每个 `<g>` 内没有继续嵌套 `<g>`；通常由文本或简单图形组成，没有 `image`、`clipPath`、`mask`、`filter` 等复杂引用。
- **处理方式**：只收集根节点的直接 `<g>` 子节点，每个 `<g>` 作为一个不可再拆分的完整组；读取 `data-name` 或 `id` 作为资源名称。
- **页面元素处理**：`workarea-background`、`print-guide-*`、出血线、内容线和背景填充不会生成图片资源；根级 `defs`、`style` 等共享定义会复制到每个组的独立 SVG 中。
- **坐标规则**：保留该 `<g>` 的原始 `transform`、子元素坐标、文字属性和 z-order，不使用位置合并，也不重新缩放组内内容。
- **输出方式**：每个顶层 `<g>` 生成一个 `Asset`，顺序按原始 SVG 文档顺序，适用于“婚礼签到册-#3.svg”这类文件。
- **失败策略**：找不到有效顶层 `<g>` 时不强行拆分，由分类器回退到整图或场景树模式。

#### 3. 场景树型 SVG：`svg_modes/scene.rs`

- **适用特征**：存在一个主容器或多层嵌套 `<g>`，包含多个 `<image>`、`<path>`、`<line>`、`<circle>` 等绘制节点，或使用 `clipPath`、`mask`、滤镜和 `use` 引用。
- **图层组快速路径**：如果发现带有“图层”或 `layer` 标识的父级 `<g>`，并且其子级 `<g>` 已分别包住图片和配套图形，则直接把每个子级 `<g>` 作为一个独立资源，不再逐节点计算或重复合并，保留父级变换和组内原始顺序，减少大型 SVG 的解析耗时。
- **处理方式**：遍历候选图层，累乘父级 `<g>` 和自身变换矩阵，将图层边界转换到 SVG 全局坐标；图片节点先建立候选组，独立巡边路径和线条按实际渲染包围盒匹配到最近图片组。
- **视觉保真**：保留原始节点 XML、`x/y/width/height`、`transform`、父级结构、裁剪、蒙版、滤镜、渐变和定义资源；组内按照原始文档顺序合成，保持 z-index。
- **尺寸规则**：优先使用 `svg_measure` 的矢量描边 tight bounds，父级变换由 usvg 的绝对变换处理，CSS px 只换算一次为毫米；没有可测描边的纯图片资源才回退到 usvg 图层包围盒。像素渲染只用于合并前后校验，不参与常规尺寸测量。
- **合并校验**：合成前后使用统一尺寸渲染并进行 RGBA 像素差比较，阈值为 `0.1%`；通过才标记合并成功，失败则按原始节点顺序拆成独立资源。
- **输出方式**：每个候选组生成独立 SVG `Asset`，`mergeStatus` 为 `merged` 或 `kept-separate`，用于复杂订单图的图片池排版。

#### 分类与隔离原则

`classifier.rs` 只读取 SVG 结构并返回 `Whole`、`TopLevelGroups` 或 `SceneTree`，不修改 XML，也不调用其它拆分器。`assets.rs` 只根据分类结果调用对应模块并统一生成资源。三套实现之间不共享候选分组状态和合并策略，新增某一种 SVG 规则时只修改对应文件，并用该类型的 fixture 单独测试。
- SVG 仅在实际排版文字时按需加载本机对应字体及必要替代字体，无文字时跳过字体加载；在规范化 SVG 中继续将文字转为路径。不会下载 @font-face 外链字体；需要精确字形应先安装字体或在原软件转曲。外部图片必须先嵌入 SVG。详见 [SVG 导入字体按需加载](SVG_IMPORT_FONTS.md)。
- 导入进度占位常驻。先显示解析状态，再接收 import-progress 的真实 completed / total，数据库事务提交成功后才显示导入完成；失败显示错误，可重试。
- 图片池、Konva 画布和左侧缩略页面统一使用规范化 SVG；卡片进入可视区域后才生成 data URL，避免一次导入几十张大图时占满 WebView 内存。
- 全部：只预览，不允许双击或拖动添加。未使用：双击或拖入 A4 添加（键盘 Enter 同样可用）。已排版：双击或 Enter 从所有页面取消排版。每个素材按唯一 assetId 判断使用状态，不依赖文件名；同名重复导入是不同素材。
- 移动及旋转结束后同步画布状态与缩略图；普通自动页面的“自动排列”统一整理当前批次已在画布上的素材并重算分页，手动表头或竖向组合使用当前页排列流程。
- 示意图进入排列页时使用上传资源的 `Asset.width/height` 计算初始尺寸并保持原始长宽比；上传阶段保存的 `sourceGroupWidthMm`、`sourceGroupHeightMm` 和 `sourceGroupBounds` 只用于标尺的物理尺寸文字。这些值来自 `svg_measure` 的矢量边界、原始 SVG 根尺寸和一次 CSS px→mm 换算，拆分资源的根 `width/height` 仍是源文件值，页面只做等比视觉缩放。放不下时只按比例缩小；分页、拖入画布、自动排列和导出共用该宽高比例，禁止把非正方形图片强制压成固定正方形。
- 自动排列按视觉表头模式合并所有对应图片，每页同一模式只生成一个自动表头。正常图片组使用统一行高 110，分页与画布共用此值，不因配件样式字段有无切换密度；同一模式优先填满可用格子，下一模式在本页容得下新表头和图片行时可拆出部分图片续排。组合重排由 `combinationReflowService.ts` 独立按当前尺寸计算，只移动图片，不改变宽高或旋转；只增高组合所在行，当前页有空则回填后续组，容不下就跨页并补上对应表头，禁止整体缩小和整页拉高行高。普通自动页面点击“自动排列”会整体重算当前画布图片的分页；手动表头和竖向组合保留当前页流程。真实 84 张批次验证为 6 页，依次 15 / 15 / 15 / 15 / 15 / 9 张，规则见模块内 `ARRANGEMENT_RULES.md`。
- 组合选择可以跨页面完成；切换页面保留 Ctrl 多选状态，执行时将两组选中的图片移动到较小页码并重排后续页面。
- 图片信息行高调整为 11 个画布单位，字段字号调整为 10 并加粗；`Size`、`Finish` 的值为空或只有空白字符时隐藏整行，后续字段、配件与备注同步上移，有值时正常展示；配件图默认占位边长为组高的 36%，备注图片默认占位边长为组高的 22%，二者仍按详情区空间等比适配；配件图增加白色圆角底板，颜色编号显示在底板内；`note` 和 `noteImage` 优先使用配件右侧独立空白区，宽度不足时放到配件下方，只展示完整内容、不显示“备注：”标签。内容保持在当前组内，主图和分页不变，画布和 SVG/PDF 导出共用布局计算。
- 图片组图片区显示最长边尺寸标识：有 `Size` 值时从该值解析最长边并统一换算为毫米（`in`/英寸 × 25.4，`cm`/厘米 × 10）；没有 `Size` 值时优先使用与资源长宽比一致的上传源分组毫米尺寸，旧资源或比例异常时把原始 `width/height` 按 CSS px（25.4/96）换算为毫米并显示 `mm`。标识方向按源分组横竖方向决定，不使用排版后的缩放尺寸；两端延长线延伸到图片中线，形成卡钳式尺寸标识，数字和单位放在尺寸线外侧；画布、SVG、PNG 和 PDF 共用同一标识布局。
- 自动排列与组合重排会把竖向图片在各自图片格内向右微移，利用右侧空白为左侧尺寸标识留出空间，最多移动 6 个逻辑单位且保留右侧 0.5 个单位的间距。仅调整位置，不缩小图片或改变分页，不挤占详情区；纵向尺寸线和文字增加组内左侧留白，重复排列不会越移越远。
- 含上传产品组的批次使用 `arrangement/compactSectionPacking.ts`：每列独立计算剩余高度，单图不随相邻高产品组被拉高，后续小组可回填该列。产品组页底部有完整空行时，从普通队列回填同一表头模式的完整图片组；剩余普通图片继续按可用空间计算多列，产品组详情宽度不会污染普通页列宽。保持图片当前尺寸、组成员与逐图标尺。确认进入排列页直接采用分页结果，避免再次排列覆盖紧凑占位；再次点击“自动排列”时按相同分离规则重算。规则见 `arrangement/README.md`。
- 产品组页中的每列独立计算剩余高度，单图不随相邻高产品组被拉高，后续小组可回填该列。普通图片页继续按图片与详情实际宽度计算列数；尺寸线贴近图片边缘，释放的图片区空间用于等比例放大图片。合并产品组详情只显示 `Size / QT / Finish / Accessory`，不显示产品名、印刷选项或其它属性。确认进入排列页直接采用分页结果，避免再次排列覆盖紧凑占位；规则见 `arrangement/README.md`。
- 产品组详情栏按可见字段计算并限制在 70–132 个画布逻辑单位，避免把一半列宽留给空白产品信息；同一模式有多个产品组时优先让两个“图片区＋必要详情区”单元共享一行，组内图片按半页排会超出整页高度时才回退到更宽的单组布局。剩余宽度优先用于图片，最多三列并保持逐图标尺可读。`Finish` 属性由桌面端读取 `printflow-data/cache/finish.json` 建立轻量索引，匹配 `name` 或 `labelZh` 后统一展示规范 `name`，空值或未匹配时隐藏。
- 导入解析期间的 SVG 临时写入项目目录 `printflow-data/temp-assets`，不会立即进入历史数据库。点击“保存批次”或确认进入示意图排列页时，Rust 将文件转移到 `printflow-data/assets`，SQLite（Tauri app_data_dir/printflow.sqlite）记录资源元数据和持久化路径；数据库只存路径，启动后按路径恢复 SVG。后续可将根目录改为设置指定目录。
- 系统保存对话框支持导出当前页 SVG / PNG，以及多页 PDF。SVG 内嵌真实 SVG 资源并保留位置旋转，PNG 使用 Rust 渲染至 A4 300 DPI（2480 × 3508）。PDF 由 Rust 使用 `svg2pdf` + `pdf-writer` 将页面 SVG 转为矢量内容，避免逐页生成 2480 × 3508 PNG 后再编码、解码和嵌入；配件图的 `attributeImages["Accessories Color"]` 地址与备注图片地址由 Rust 并发下载并转为内嵌 `data:` 图片，按 URL 缓存，超过 768 像素的栅格图限制最长边后再嵌入，确保 PDF 中可见。原始 SVG 中的其它外部 `image` 不会在导出时被误请求，加载失败会直接返回错误而不生成缺图 PDF。
- 排列页导出格式默认是 PDF。点击导出后显示半透明遮罩、加载动画和真实页级进度条；Rust 每完成一页发送 `pdf-export-progress`，前端显示“正在处理第 X / Y 页”，成功、取消或失败后解除遮罩并恢复操作。

### PDF 大批次性能验证（2026-09-16）

- 当前真实批次包含 84 张 SVG 资源，自动排列成 6 页；SVG 内嵌 88 个 PNG、约 2.16 亿像素。开发版依赖未开启编译优化时，后端导出实测 159.5 秒，主要耗时在像素处理和 PDF 转换。
- `src-tauri/Cargo.toml` 对相关依赖单独开启 `opt-level = 3`，不改变页面布局、矢量内容或内嵌主图质量；同一批次两次复测分别为 27.180 秒、27.198 秒。前端生成页面 SVG 约 1.13 秒，此处后端计时不含保存对话框及 WebView IPC。
- 已核对全部 6 页，88 个内嵌主图 PNG 的尺寸、像素和透明度与源文件一致，3 张配件图存在且可见；仅编译优化前后的所有页面在 96 DPI 下的渲染像素一致。
- 后续将 Windows 页面导出字体拆到 `src-tauri/src/fonts.rs`：直接读取 Arial 与微软雅黑的 6 个固定字体文件（本机含 8 个字形集合），独立缓存，不遍历 5000 多个系统字体。指定备选为 Segoe UI / 宋体，原始 SVG 导入的特殊字体解析策略保留。
- 字体初始化独立进程实测从 6273 个字形集合 / 6627 ms 降到 8 个 / 4 ms，完整批次后端导出为 25.755 秒。6 页文本和所有图片像素均核对通过；页眉中文从旧的自动回退“等线”改为页面指定的微软雅黑，因此页眉字形会有变化，正文渲染像素一致。
- 导出日志保留各阶段耗时；真实批次回归测试直接调用应用使用的 `export_pdf` 命令。复现、输出文件和限制见 [PDF 导出性能验证](PDF_EXPORT_PERFORMANCE.md)。

## 当前限制与后续

- 单个文件上限 35 MB，PNG 上限 4000 万像素，拆分上限 500 个顶层图形。
- SQLite 只保存规范化 SVG，preview / thumbnail 字段保留兼容但不再复制整份 SVG；界面按需生成 SVG data URL。大量素材时后续可继续接入磁盘资源文件和虚拟列表。
- 大型 SVG 拆分时 Rust 不再克隆整批候选节点，也不为每个素材重复解析一次规范化 SVG；场景解析阶段会持续发送进度，前端显示“正在分析 SVG 场景树”。
- 拆分资源按 8 张一批通过 `import-asset-batch` 事件推送，前端边解析边追加图片列表；批量推送避免为每张大 SVG 单独触发一次 IPC 和 React 重渲染。导入区显示“解析 SVG 图层”和“生成图片资源”两条进度条，活动条带有流动渐变动画。
- 页面复制、删除、排序、任意尺寸编辑、手动缩放 / 平移、多选、智能生产拼版、订单接入与账号管理尚未实现。
- 产品 A/B/C 暂为固定选项，真实产品配置后续接入。

### 批次信息

图片上传页在上传区域下方提供批次元数据表单：客户名称、Drawing Date（绘图日期）、Estimated Ship Date（预计发货日期）和 Designer（来源）。Designer 默认使用当前软件账号名“张三”，其余字段由员工填写。表单状态由 React 交互维护，保存批次或确认生成示意图时通过 Tauri IPC 传给 Rust；Rust 将元数据与素材清单一并写入项目目录下的 SQLite 历史记录。打开历史批次时，元数据从 SQLite 返回并恢复到表单，临时批次不会写入历史记录。
历史记录卡片标题使用客户名称；客户名称为空时显示“图片批次”作为默认标题。
界面返回批次列表时先立即清空当前批次并切换列表，临时文件清理由 Rust 在后台执行，避免等待磁盘操作造成界面停顿；打开历史批次直接同步显示记录内容。
历史记录与当前批次列表采用方向动画：打开历史批次时内容从右向左进入，返回历史记录时内容从左向右进入；动画不阻塞数据切换，并尊重系统减少动态效果设置。
上传卡片顶部提供“图片上传 / 图片属性”标签：默认显示文件上传和解析进度；切换到图片属性时显示当前批次的图片名称及尺寸列表，列表可滚动且不重复加载图片数据。
“图片属性”页签仅显示属性编辑提示和由本地产品配置生成的下拉框，不在右侧重复渲染上传图片列表。
上传图片列表支持方形选择框：普通点击单选，Ctrl（或 macOS Command）点击可多选，Shift 点击可选择起止图片之间的连续范围；“图片属性”页签同步显示操作提示。
图片列表普通点击卡片空白、文字或选择框时只选中当前图片，再次点击仍保持选中；Ctrl（或 macOS Command）点击切换该图片的选择状态，Shift 点击追加连续范围。缩略图不参与选择，单击直接放大预览；“全选 / 取消全选”按钮保持可用。
“全选 / 取消全选”右侧提供独立的“取消选择”按钮，用于清空当前全部选中项；无选中项时禁用，不修改图片、属性或批次内容。
上传卡片的页签内容采用方向滑动过渡：切换到图片属性从右向左进入，切回图片上传从左向右进入，并支持减少动态效果设置。
当前图片上传入口仅接受 SVG：文件选择器过滤为 svg，拖拽上传也会拒绝 PNG、JPG 等其他格式。

### 产品选项缓存

#### 属性面板与自定义产品

- 上传页保持固定窗口布局：左右面板允许收缩，右侧 `upload-tab-content` 单独纵向滚动；图片属性和选中说明过长时不会撑高整个软件，顶部标签和底部“生成示意图”保持可见。
- “图片属性”的产品选择区域提供“已有产品 / 自定义”切换。已有产品继续使用接口缓存和联动选项，自定义独立于远程缓存加载失败状态。
- 当当前选中图片全部使用 `custom:<本地ID>` 产品时，属性页签自动滑动到“自定义”；选中已有产品或混合选择时自动保持“已有产品”。
- 自定义表单包含产品、尺寸、印刷选项、样式、配件颜色、QT。QT 为 1–2147483647 的整数，产品名称必填。保存时由 Rust 验证并清理字段首尾空格。 自定义表单下方可上传配件颜色图片（SVG、PNG、JPG、WEBP，35MB 内），由 Rust 读取并写入本地自定义产品记录，重新载入时恢复预览。
- “保存到本地”保存常用配置；“保存并应用到选中图片”先保存配置，再将六个字段一次性赋予当前选中项，不改未选中图片。“已保存的自定义产品”可重新载入，“新增”开始另一条配置。修改并保存沿用原配置 ID。
- 保存位置：项目 `printflow-data/custom-products.sqlite`，表名 `custom_products`。读写通过 Rust 的 `list_custom_products` / `save_custom_product` 异步命令完成；前端不使用 localStorage 存储数据。
- 自定义产品资产使用 `productId: custom:<本地ID>` 和 `productName`；属性沿用 `Size`、`Print Option`、`Finish`、`Accessories Color`、`QT`，图片地址写入 `attributeImages["Accessories Color"]`。应用完整配置会清除原产品的属性和关联图片地址，随后使用原有批次保存与排版流程。
- 模块划分：`ProductAttributesPanel.tsx` 负责属性区与来源切换，`CustomProductForm.tsx` 负责自定义交互，`customProductService.ts` 负责命令调用与资产映射，Rust `custom_products/storage.rs` 负责本地持久化。
- 验证：42 张图片在 1100×700 窗口下只有面板内部滚动；自定义保存与重新载入、仅应用选中项验证通过；Rust 文件数据库关闭再打开、稳定 ID 更新及无效输入回滚测试通过。

产品选项接口在每次 Tauri 启动进入页面后由 Rust 命令请求一次，页面会显示“正在请求产品配置接口…”提示，完成后提示缓存已更新；失败时提示并继续使用上次有效缓存。响应先校验 JSON，再写入项目目录 `printflow-data/cache/product-configs.json.tmp`，最后原子替换为 `product-configs.json`，避免大 JSON 写入中断造成损坏。页面下拉框始终从本地缓存读取，接口请求不会阻塞界面。`refresh_product_configs` 是唯一的刷新入口。响应使用分块读取并限制为 32MB，防止异常响应一次性申请数百 MB 内存。
## 图片属性产品选项

“图片属性”页签使用 Rust 缓存的 `printflow-data/cache/product-configs.json`，前端通过 `load_product_configs` 读取，不在切换页签时直接请求 8.7MB 接口。缓存根节点的 `products` 数组会被规范化为产品下拉框和 `productOptions` 选项下拉框；产品、选项和值都会过滤 `hidden`、`isHidden`、`deleted`、`isDeleted`、`showInEditor=false` 与 `editorVisible=false` 项，并优先显示 `labelZh` 中文名称。可见性标记兼容布尔值、`0/1` 和常见字符串值，避免旧缓存把隐藏选项误显示出来。带 `linkedParent` 的选项遵循 JSON 中值的 `parentValues` 联动规则：父选项未选择或当前值不匹配时隐藏，匹配后才展开对应下拉框。缓存不可用或解析失败时只显示错误提示，不阻塞图片上传流程。

属性赋值由左侧图片卡片的受控多选状态驱动。上传和打开历史批次默认不选中图片，批次顶部的“全选”按钮可一次选中当前批次；在“图片属性”页签修改产品或任一选项后，变更会立即写入所有选中资源的 `productId` 和 `attributes`，保存批次或生成示意图时由 Rust 一并持久化。卡片显示 `NO` 序号及已写入的产品和属性。
- 选中图片变化时，右侧属性面板按公共值回填：所有选中图片的产品相同才回填产品；某个属性在所有选中图片中相同（包括都为空）才回填该属性，不同值的属性保留右侧原有选择。公共值在渲染时从选区派生，属性编辑过程中不会被反向覆盖。
- 图片属性表单末尾提供 `QT（数量）` 整数输入框，最小值为 1；修改后仅写入选中图片的 `attributes.QT`，不会改动产品、印刷或其他属性，保存批次和生成示意图时由 Rust 持久化。选中图片的 QT 相同会自动回填，不同则保留当前输入值；更换产品会连同 QT 一起清空。
- 选项值关联的图片地址按图片资产单独写入 `attributeImages`，键名与选项名一致，例如 `attributeImages["Accessories Color"]`；示意图画布的配件图只读取这个精确键名，字段为空时留空，不回退到产品配置中的其它图片；切换或清空该选项时同步更新或删除，保存批次由 Rust 一并持久化。
更换产品时会清空所选图片已有的全部属性，并清空属性页签中的选项值，必须按新产品规则重新选择；卡片保存产品 ID 作为内部关联，同时展示配置中的实际产品名称。

#### 属性联动与选项图片

- `services/productOptionRules.ts` 统一处理父子选项联动。子选项必须先按 `linkedParent` 和 `parentValues` 过滤值，再显示下拉框；不能仅判断子选项是否可见就展示其全部值。父值匹配忽略首尾空格和大小写。
- 同一父值下，重复的 `name` 只展示配置中的首项，确保 Ant Design 下拉选项的 value 唯一，避免虚拟列表重复渲染同一个标签；不改写本地原始配置。不同父值下的同名选项分别保留。
- 更换或清空父选项时，递归清除所有下级选项的值，包括当前未显示的下级；页面表单和所有选中图片的 `attributes` 同步更新，未选中图片不修改。清除使用删除字段，保存批次时不再携带旧颜色。
- `components/ProductOptionField.tsx` 负责单个属性下拉框与图片展示。所选值有 `image` 时在对应下拉框下方展示，选项本身有 `image` 时作为兜底；图片等比显示、按需加载，可点击放大。切换值同步换图，无图片时不留空白占位，加载失败显示提示。
- 回归测试：`tests/product-options.test.mjs` 覆盖父值过滤、重复值、同名不同父值、级联清空和产品切换；浏览器使用真实缓存中的 Clear Acrylic Keychains 验证配件样式、配件颜色、图片预览以及批量保存参数。

卡片产品名称与产品下拉框共用同一份本地配置，按 `productId` 匹配下拉选项的 `title`（显示标签），不再回退显示数字 ID。旧批次即使没有保存 `productName` 也可自动解析名称；配置中缺少该产品时使用已保存名称，仍无法解析时显示“产品配置不可用”。读取配置使用共享请求，不会因卡片数量或页签切换反复读取大 JSON。长产品名称自动换行，也可以悬停查看完整名称。

### 大批次确认性能

图片已写入 `temp-assets` 时，保存/确认只通过 Rust 传递资产元数据和临时文件路径，不重复把完整 SVG 通过 IPC 发送。Rust 的批次去重使用流式 FNV-1a 内容摘要和字节数，不再把每个 SVG 拼进历史签名 JSON；持久化完成后只返回紧凑元数据，前端继续使用内存中的 SVG 进入排列页。Rust 日志会记录 `save_batch phase=signature/persist` 的资产数和耗时，便于定位大批次瓶颈。

### 进入排列页前的产品分类

点击“生成示意图”后先按 `productId` 统计产品数量，产品按总数从多到少排序；同一产品内再按印刷选项（配置中的 `Print Option` / `Print` / `印刷选项` / `印刷` 属性）统计数量，从多到少排序；每级数量相同时保持原始顺序。分类期间按钮显示加载动画并禁用，分类完成后才打开确认弹窗，确认后分页使用已分类顺序。
