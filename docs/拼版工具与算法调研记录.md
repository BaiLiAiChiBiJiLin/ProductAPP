## 2. GitHub 调研结果

### 2.1 `binpack2d`：矩形装箱

项目地址：[InfinityTools/binpack2d](https://github.com/InfinityTools/binpack2d)

- Rust 实现，MIT License。
- 支持任意矩形的二维装箱，核心基于 Jukka Jylänki 的 RectangleBinPack 研究。
- 提供 MaxRects 及其变体，适合以利用率、板材数量和剩余空闲区域为目标进行搜索。
- 可处理旋转、多个 bin、未放置矩形和占用率统计。
- 适合作为当前矩形模式的服务端算法，前端只接收 placement 结果。

矩形和异形模式的统一评分顺序建议为：

1. 在有效区域内放置最多图片；
2. 尽量减少使用的板材数量；
3. 提高有效区域利用率；
4. 尽量减少剩余空隙；
5. 图片之间保持版面配置中设定的间距。

前四项用于比较排版结果，第 5 项作为硬约束校验：图片之间的距离小于设定值时，该结果不可提交。默认图片间距为 **3 mm**。

界面提供三种计算目标：**最少板材**优先减少板材数量，**最少切割线**优先减少可复用的切割布局数量，**综合最少**在已放置图片数量相同的前提下，对板材数量和切割布局数量采用等权评分（`板材数 + 切割布局数`），再以利用率作为并列比较项。

### QT 优先与余隙补排

排版请求保留基础图片的 `quantity`，不把 QT 副本先展开成上千个轮廓。每个候选板材按以下顺序处理：

1. 按基础图片 QT 从高到低排序；同 QT 时按面积从大到小排序。
2. 用当前图片批次填充板材，并保留 MaxRects 产生的互不重叠空闲矩形。
3. 当前批次无法继续放置后，立即在同一块板材的边界、已有图片边缘和空闲矩形中尝试低 QT/单张图片，分别测试 0°、90°、180°、270°。
4. 新图片必须同时满足有效区域边界和 `spacingMm + 0.01 mm` 的安全间距；完成一块板材后，再把后续板材上的图片反向尝试移回前面的余隙。
5. 对数量相同的完整结果，再按“已放置数量 → 目标评分 → 利用率”比较。放置数量是硬约束；综合目标使用 `板材数 + 切割布局数` 等权评分，最少切割线目标优先可复用的完整位置/旋转布局。

这套流程保证低 QT 图片不会因为高 QT 批次先占用空间而被直接推到新板材，同时避免为了试探余隙而复制全部轮廓。矩形模式使用真实毫米宽高；异形模式只对每种基础轮廓建立一次几何数据，最终才映射为 `id#qt-N` 的 Konva 实例。

真实资产回归（板材 300 × 464 mm，有效区域 285 × 440 mm，右侧距 5 mm，图片间距 3 mm）记录如下：

| 数据集 | QT 总数 | 模式 | 放置 / 板材 | 利用率 | 重叠 | 间距不足 | 越界 | 计算耗时 |
| --- | ---: | --- | ---: | ---: | ---: | ---: | ---: | ---: |
| `ds_202610091159`，84 个 SVG | 1005 | `binpack2d/MaxRects` | 1005 / 35 | 83.93% | 0 | 0 | 0 | 3171 ms |
| `Backup_of_naomi hannah_202610091507`，4 个 SVG | 65 | `binpack2d/MaxRects` | 65 / 3 | 59.8% | 0 | 0 | 0 | 4 ms |
| 同一 Backup 数据，异形选择 `sheetnest` | 4 | 轮廓复杂度分批并返回真实轮廓 placements | 4 / 1 | 11.0% | 0 | 0 | 0 | 35 ms |
| 同一 Backup 数据，异形选择 `ironnest` | 4 | `ironnest` 真实轮廓搜索 + 余隙补排 | 4 / 1 | 11.0% | 0 | 0 | 0 | 4120 ms |
| `ds_202610091159` 前 4 个 SVG，异形选择 `ironnest` | 4 | `ironnest` 真实轮廓搜索 | 4 / 1 | 5.5% | 0 | 0 | 0 | 4689 ms |

异形真实轮廓的采样点数量和独立轮廓类型同时过大时会触发分批预算。当前结果会明确返回被剔除的基础图片 ID 和原因，正常轮廓继续返回真实 placements，不再生成矩形安全兜底。所有报告同时保存请求、放置坐标和碰撞/间距/越界校验结果。

本轮真实轮廓回归还对求解结果做了多边形级校验（旋转后的边相交、包含关系和轮廓最小距离），不再用旋转图片的外接矩形误报异形重叠。`ds_202610091159` 前 4 个 SVG 使用 `ironnest` 时放置 4/4、1 块板材、重叠 0、间距不足 0、越界 0；`Backup_of_naomi hannah_202610091507` 的 4 个 SVG 放置 4/4、1 块板材、利用率 11.0%、上述校验均为 0。后者有一张图片原先被采样候选漏掉，新增的保守矩形余隙补排将其放回同一板材；补排要求完整毫米外接框满足 3 mm 间距，因此不会牺牲异形轮廓安全性。

### 2.2 `sheetnest`：异形套料

项目地址：[YJack0000/sheetnest](https://github.com/YJack0000/sheetnest)

- Rust 核心，同时提供 Python、JavaScript 和 WASM 绑定，许可证为 Apache-2.0 或 MIT。
- 面向不规则多边形嵌套，使用 NFP 判断两个零件在不同旋转状态下的可放置区域。
- 使用遗传算法搜索零件顺序和旋转组合，并缓存成对 NFP 以降低重复计算。
- 支持板材宽高、边距、零件间距、正交旋转、自由旋转、旋转步长、曲线容差和时间限制等参数。
- 适合后续接入透明图片轮廓或 SVG 路径，按真实轮廓而不是外接矩形进行排版。

异形模式需要特别注意：自由旋转和复杂曲线会明显增加计算量；当前方案采用有限候选/代数预算和多次搜索，不能承诺每次都得到数学意义上的全局最优。带孔图片、孔内套料等能力需要在接入前单独验证。

### 2.3 `ironnest`：确定性异形套料

项目地址：[TexasCoding/ironnest](https://github.com/TexasCoding/ironnest)

- Rust 核心，MPL-2.0 许可证，当前项目通过固定 Git revision 接入，避免算法版本漂移。
- 接口直接接收毫米多边形、板材轮廓、最小间距、允许旋转角、seed 和固定预算，返回放置项、坐标和旋转角。
- 默认实现是确定性的采样候选放置，并按 0/90/180/270° 尝试方向；它不是界面上曾经误标的 NFP 求解器。
- 适合在空余条带中继续寻找小图片的放置位置，但大数量或多轮廓类型会快速放大计算量。
- 当前界面在选择“异形拼版”后可切换 `sheetnest` 或 `ironnest`，两者结果都继续使用统一的图片数量、板材数量、利用率和切割布局评分。

`ironnest` 已通过 Cargo Git 依赖接入 Rust 后端，`pack_irregular_ironnest` 会直接调用 `ironnest::nest(...)`，不是前端模拟或仅显示算法名称。小型有效 SVG 的回归测试要求返回 `ironnest/候选采样...` 结果；无法安全处理的轮廓会写入 `excludedItems`，不会切换成矩形结果。

`ironnest` 的上游仓库要求较新的 Rust 工具链，因此项目 MSRV 已提升到 Rust 1.88；实际交付版本由 `Cargo.lock` 固定。

### 2.3.1 异形计算的资源保护

异形算法会在原生代码中构造轮廓缓存；轮廓类型数量和采样点数增大时，内存和耗时会呈平方或更高增长。当前实现会在进入原生求解器前校验 SVG 轮廓、拆分 `MoveTo` 子路径、清理重复/共线点，并按“轮廓复杂度”分批。超过单图预算、自交、退化或过大的 SVG 轮廓会写入 `excludedItems` 并在右侧标红；其他图片继续使用真实轮廓排版。worker 异常只影响该批次，不会让 Tauri 主进程被 foreign exception 一起终止。

### QT 数量的内存策略

前端读取每张基础图片的 `QT` 属性，但异形请求只发送一次基础图片记录：`id`、真实毫米宽高、`quantity` 和一份毫米轮廓。Rust 端按轮廓键合并相同形状，`sheetnest`/`ironnest` 只为基础轮廓建立几何数据；求解结果生成放置项时才按数量映射为 `id`、`id#qt-2`、`id#qt-3` 等实例 ID，供 Konva 复用同一个图片资源显示。

这会消除“84 张基础图片被 QT 展开成 1000 多份后重复提取轮廓”的主要开销。QT 不再触发 600 个副本上限；求解器按数量生成位置，复杂度过高时按基础轮廓分批，并把无法安全处理的具体图片写入 `excludedItems`。

### 2.4 几何库：Clipper2 / Clipper

项目地址：[Clipper2 TS](https://github.com/countertype/clipper2-ts) 、[Clipper Lib](https://github.com/junmer/clipper-lib)

这类库是几何辅助库，不是完整的拼版求解器，主要用于：

- 多边形并集、交集、差集和异或；
- 对图片轮廓、有效区域和安全间距做 offset；
- 生成或校验碰撞区域；
- 在导出 SVG 前清理自交路径和无效几何。

输入轮廓必须先转换到毫米坐标，再交给几何库；不要让像素值和毫米值在同一套几何运算中混用。

### 2.5 交互和导出

- [Konva](https://konvajs.org/) 用于交互画布。它负责 Stage、Layer、Image、Transformer、拖动和视口变换，不负责决定最佳排版。
- SVG 是结果交换和印刷导出格式。导出时直接使用协议中的毫米坐标，并把图片资源、路径和变换写入 SVG；交互缩放只改变视口，不改变数据层尺寸。

### 2.6 参考软件的轮廓处理与当前实现的对应关系

参考资料描述的“曲线采样、多边形偏移、包含判断、相交检测、智能分组”是异形拼版前的几何准备和校验流程，不能单独等同于完整的套料算法。当前采用的 `sheetnest` 已经在内部使用 Clipper2 完成这些关键步骤：

- `inflate_ring` 对零件按间距做轮廓偏移，等价于以 `ClipperOffset` 生成安全间距区域；
- `point_strictly_inside` 用于 NFP 和禁放区域的包含判断；
- Minkowski/NFP 和相交运算用于计算候选位置以及验证重叠；
- `Part` 的几何缓存按轮廓类型建立，前端 QT 副本在后端按数量传入，避免为完全相同的轮廓重复建立 NFP 缓存。

因此不再在 `sheetnest` 外层重复做一次偏移和碰撞，否则会扩大轮廓并造成双重间距。当前新增的外层处理负责曲线采样、拆分 SVG 多子路径、去除重复/共线采样点、校验面积和点数；算法返回后仍需按有效区域、轮廓间距和重叠规则复核。旧版 `corelapp_2.cpg` 受保护，不能仅凭 Win32 区域 API 命名确认它采用了 NFP、底部左侧、遗传算法或模拟退火中的某一种。

### 2.7 拼版设置中的工具目录和真实接入状态

拼版设置的异形算法下拉现在按以下三组展示研究结果：

- **已接入（完整排版器）**：`sheetnest`、`ironnest`、`SVGnest`、`PackingSolver`、`Spyrrow`、`pyFit-agentic-polygon-nesting`、`CAD-N`。它们会实际计算图片在板材上的位置并返回板材布局；适配器只接收/返回毫米 JSON。SVGnest 是浏览器 Worker 试验实现，失败或超时会直接返回错误，不生成矩形安全兜底。
- **已接入（几何核心 + 本地排版桥）**：`Deepnest-next`。当前调用官方 `@deepnest/calculate-nfp` C++ NFP 核心，再由本项目执行确定性的候选点/碰撞校验和贪心排版；它能输出实际板材布局，但没有启动 Deepnest Electron 的完整遗传搜索，因此不能把它描述成完整 Deepnest GA。
- 研究阶段确认过但当前运行时没有可用适配器的项目（OpenNest、libnest2d、PyNest2D、Logo Nest Studio、Nest4J、2D-Irregular-Packing-Algorithm、jagua-rs、libnfporb）不再出现在产品下拉框中，也不参与运行时分发。它们只保留在本节的调研记录中，避免把“能研究”误认为“当前能拼版”。

第一类“完整排版器”表示确实调用了对应项目的排版核心并返回图片位置；第二类也会返回实际板材布局，但只复用了 Deepnest 的 NFP 几何核心，候选搜索由本地桥接策略完成；“几何参考”只能算轮廓、NFP 或碰撞区域，不能单独产生完整板材布局。外部适配器还会检查未放置项、有效区域和间距，失败时返回错误，不会把失败结果伪装成 `sheetnest`。

本轮适配器冒烟结果（同一批毫米三角形 QT=3、间距 3 mm）如下：

| 引擎 | 类型 | 结果 |
| --- | --- | --- |
| `PackingSolver` | 官方 C++ irregular Python wheel | 3/3，1 块板材 |
| | `Spyrrow` | 官方 PyO3 Sparrow 封装 | 3/3，1 块板材 |
| `Deepnest-next` | 官方 `calculate-nfp` C++ bridge + 候选搜索 | 3/3，1 块板材 |
| `pyFit` | 官方 Python NFP-BLF | 3/3，1 块板材 |
| `CAD-N` | 官方 Python free-rectangle engine | 3/3，1 块板材 |

`Deepnest-next` 还用真实 ds SVG 的前 2 个轮廓验证通过，得到 2/2、1 块板材；复杂轮廓会进行最多 384 点的保形采样，避免 NFP 缓存导致内存爆炸。可重复命令见 当时的外部适配器说明（这些脚本与安装说明已随引擎移除）。

本轮自动化验证覆盖：Rust 后端 20 个算法单测、TypeScript 类型检查、拼版 UI/算法目录/矩形回归共 14 个前端测试；真实数据还运行了矩形、`sheetnest` 和 `ironnest` 模式。真实报告保存在 `.tmp-real-nesting-final/`，包含原始请求、放置坐标、未放置项和 contour-level 校验字段，便于之后把外部工具接入后做横向比较。

## 4. 统一毫米协议

### 4.1 请求结构

所有尺寸、坐标、边距、间距和旋转后的几何数据均使用毫米。图片原始像素仅用于加载资源和生成预览，不进入排版计算。

```ts
type NestRequest = {
  mode: 'rectangle' | 'irregular'
  sheet: {
    widthMm: number
    heightMm: number
    effectiveWidthMm: number
    effectiveHeightMm: number
    effectiveRightMarginMm: number
    spacingMm: number
  }
  items: Array<{
    id: string
    quantity: number
    widthMm: number
    heightMm: number
    // 异形模式使用，点坐标为图片本地毫米坐标
    polygon?: Array<[xMm: number, yMm: number]>
    rotationsDeg: number[]
    sourcePath?: string
  }>
}
```

当前板材默认值：

```text
板材宽：300 mm
板材高：464 mm
有效宽：285 mm
有效高：440 mm
版面孔：直径 3 mm，数量 2 个
版面孔间距：203.468 mm
版面孔左侧距：4 mm
有效区域右侧距：5 mm
图片间距：3 mm
```

### 4.2 返回结构

```ts
type NestPlacement = {
  itemId: string
  instance: number
  sheetIndex: number
  xMm: number
  yMm: number
  rotationDeg: number
  // 异形模式可返回变换后的轮廓，便于前端和导出复用
  polygon?: Array<[xMm: number, yMm: number]>
}

type NestResult = {
  placements: NestPlacement[]
  unplaced: Array<{ itemId: string; instance: number; reason: string }>
  sheetsUsed: number
  utilization: number
  elapsedMs: number
}
```

### 4.3 坐标和精度约定

1. 板材左上角是板材坐标原点 `(0, 0)`，x 向右、y 向下。
2. 有效区域的左边界为 `sheet.widthMm - effectiveRightMarginMm - effectiveWidthMm`，上下按有效高在板材高内垂直居中。
3. `xMm`、`yMm` 是排版对象在板材坐标系中的放置坐标；矩形模式以图片左上角为锚点，异形模式以图片本地轮廓原点为锚点。
4. 旋转在毫米坐标中计算，Konva 的像素坐标只由 `mm * viewportScale` 得到；缩放和平移不能回写到业务尺寸。
5. 服务端序列化建议保留至少 3 位小数，导出时避免把毫米坐标提前取整。

## 5. 排版、编辑和导出流程

```text
生产图片记录（文件路径、真实宽高 mm、SVG 路径）
        ↓
矩形模式：直接使用图片真实宽高 mm
异形模式：从 SVG 路径提取多边形轮廓并转换为 mm
        ↓
NestRequest（统一 mm）
        ↓
Rust：binpack2d 或 sheetnest
        ↓
NestResult（板材序号、x/y mm、旋转角）
        ↓
Konva：按视口比例渲染并允许拖动/旋转
        ↓
再次校验：有效区域内、图片之间无重叠、间距满足要求
        ↓
SVG：使用最终毫米坐标导出
```

人工调整时必须执行以下规则：

- 图片可以自由移动和旋转；
- 图片可以紧贴有效区域边界，但不能超出有效区域；
- 图片之间不能发生相交，异形模式按真实轮廓校验，矩形模式至少按旋转后的矩形校验；
- 修改未通过校验时不提交位置，或恢复到上一个有效位置；
- 后续算法重新排版时，以数据层的毫米坐标为准，不读取 Konva 的像素位置。

## 6. 性能和质量边界

- 拼版问题属于组合优化问题，不能仅靠一次贪心排序保证最优；生产环境应设置时间上限、候选排序和多次随机种子。
- Konva 的像素密度只影响显示清晰度和 GPU/内存开销，不改变毫米数据和 SVG 导出质量。导出不依赖画布截图，因此可以保持原始图片质量。
- 大量图片时应使用图片缓存、视口裁剪和分层重绘；排版求解放在 Rust 后端，避免在主线程阻塞拖动和缩放。
- `sheetnest` 的曲线容差、自由旋转和复杂轮廓需要用真实生产图片做基准测试，再确定默认值。
- 每次算法升级都应保存同一批输入的 `NestRequest` 和结果，用板材数量、利用率、耗时、未放置数量和碰撞校验结果做回归比较。

## 8. DesignCraft 参考结论（storytold/designcraft）

本次下载并检查了 [`storytold/designcraft`](https://github.com/storytold/designcraft)。它是一个用 Rust 编写的 InDesign 类页面排版工具，重点是页面、母版、文本框、图文框、对齐辅助线和跨平台渲染。源码中没有发现 NFP、bin packing、异形套料或材料利用率优化实现，因此不把它作为当前拼版求解器使用；当前求解器仍采用 `binpack2d`、`sheetnest`/`ironnest` 和 `Clipper2`。

可以迁移到本项目的交互设计：

1. **几何、交互和渲染分层**：DesignCraft 将 `geom`、文档模型、工具交互和渲染拆开。我们的数据层继续统一使用毫米，Konva 只负责毫米到屏幕像素的变换，SVG 导出直接使用毫米坐标。
2. **视口变换对象**：画布统一维护原点、缩放和视口旋转，并实现 `fit` 与“以鼠标位置为中心缩放”。这与当前 Konva 画布的需求一致，缩放不能修改业务坐标。
3. **Begin / Preview / Commit 手势事务**：拖动、旋转时只更新预览状态，释放鼠标后提交一个命令，撤销时只产生一个历史步骤。预览阶段可实时做碰撞、有效区域和间距校验。
4. **分层吸附管线**：可按“版材边缘 → 网格/辅助线 → 其他图片边缘 → 3 mm 等距 → 尺寸”顺序生成候选位置；吸附容差从屏幕像素换算成毫米。最终提交前仍需用矩形或真实轮廓做碰撞复核。
5. **等距吸附和智能辅助线**：移动图片时除边缘吸附外，比较相邻图片的间隙并给出等距候选；发现间距小于配置值时拒绝候选位置。这比每次只取最近 x/y 坐标更适合当前的手动微调需求。
6. **可见区域渲染和缓存**：只重绘可见板材/对象，图片资源按源图缓存，拖动时更新轻量预览层；碰撞计算放在 Rust worker，避免大量 QT 副本阻塞 UI。我们的 QT 基础轮廓策略与这种缓存方向一致。
7. **命令边界和可恢复性**：把每次排版请求、算法选项、随机种子和结果保存为可重放的 JSON，便于比较“最少板材 / 最少切割线 / 综合最少”和复现异常。Rust worker 通过有限输入、分批和结构化诊断返回结果，不用固定墙钟超时杀掉正在搜索的异形任务。

DesignCraft 的几何库内部使用 point 作为文档单位，并支持 mm 等测量值的解析；本项目不照搬 point 作为业务单位，仍以毫米作为唯一输入输出，只借鉴单位解析、有限值校验和屏幕变换的边界设计。

相关源码：[`README`](https://github.com/storytold/designcraft/blob/main/README.md)、[`架构说明`](https://github.com/storytold/designcraft/blob/main/docs/architecture.md)、[`画布变换与鼠标中心缩放`](https://github.com/storytold/designcraft/blob/main/crates/ui-egui/src/canvas.rs)、[`吸附管线`](https://github.com/storytold/designcraft/blob/main/crates/tools/src/snap.rs)、[`工具事务`](https://github.com/storytold/designcraft/blob/main/crates/tools/src/lib.rs)。

## 9. SVGnest 试验算法

[`SVGnest`](https://github.com/Jack000/SVGnest) 是 MIT 许可的浏览器异形套料工具，采用 NFP（No-Fit Polygon）和遗传算法，支持凹形轮廓、间距、旋转、孔洞内嵌和多板材目标。它的 README 明确说明计算依赖 SVG 和 WebWorker，且计算量较大；其默认适应度顺序是先放置更多图片、再减少板材、最后减少排版宽度，与本项目的评分顺序接近，但还没有直接提供“最少切割布局”目标。

本项目已在“拼版设置 → 异形算法”加入 `SVGnest（NFP-GA，试验）`，并将原版脚本放在 `public/svgnest/`，通过浏览器 Worker 运行。输入仍先转换成毫米坐标的 SVG 路径，输出再转换回统一毫米协议和 Konva placement。SVGnest 试验模式最多处理 260 个实例，使用最多 24 轮有限遗传搜索作为自身结束条件；达到轮数后返回当前最佳候选，不再依赖 2.5 秒墙钟定时器，也不自动切换到矩形算法。

画布交互已增加 `DragTransaction`：拖动期间只移动 Konva 节点并保留最后一个有效预览，释放鼠标后一次提交跨板材移动；候选位置按版材边缘、图片间距和相邻等距顺序吸附。碰撞检测先用每块板材的均匀网格空间索引筛选候选，再对旋转矩形或真实 SVG 多边形做窄相位检测，间距小于配置值时拒绝移动。

SVGnest 来源：[`README`](https://github.com/Jack000/SVGnest#readme)、[`SVGnest LICENSE`](https://github.com/Jack000/SVGnest/blob/master/LICENSE.txt)。

## 10. Pressria Bridge 参考架构

本项目还对本机安装的 Pressria Bridge 1.5.0 做了只读分析，完整证据记录见 [`pressria-bridge-analysis.md`](../pressria-bridge-analysis.md)。它值得借鉴的地方不是某一个“神奇算法”，而是把轮廓、策略、余料和输出拆成连续的阶段：

```text
订单/PDF/SVG
  → 轮廓提取与采样
  → 产品分组与轮廓类型缓存
  → 同款 Grid/行扫描 或 多款 NFP/IFP
  → 余料差集与跨组补排
  → 压紧、间距和重叠复核
  → 带 UUID/位置/旋转的 placement SVG
```

### 10.1 策略分流

- 一个轮廓类型且数量大于等于 2 时，优先使用 Grid/行扫描候选点；它只在行、上一行和新行边界产生少量候选，再用真实轮廓检查碰撞，适合同款钥匙扣、贴纸和立牌批量排版。
- 多轮廓混排或数量为 1 时，使用 NFP/IFP：IFP 限制图片参考点只能落在有效区域内，NFP 描述与已放图片不能相交的位置，再对候选区域做间距偏移和评分。
- 当前 Rust 路径已经按基础图片的轮廓键合并 QT，数量在求解后映射成 `id`、`id#qt-2` 等实例。对单一轮廓且超过原生 GA 数量预算的任务，改用受控的 `ironnest` 轮廓采样安全路径，保留真实轮廓，避免直接退回矩形。

### 10.2 轮廓类型缓存

轮廓缓存的键应包含毫米尺寸和规范化轮廓点列。SVG 不同导出器可能选择不同的起点或顺逆时针方向；当前后端已对环的循环起点和绕行方向做规范化，因此同一轮廓只建立一次几何数据。旋转仍由求解器显式尝试，不能把旋转后的坐标直接覆盖到原始图片坐标上。

轮廓缓存只缓存几何数据，不缓存 QT 的图片位图。图片资源继续由 Konva 按源路径复用，导出阶段再按 placement 的 UUID、毫米坐标和旋转角度放回真实 SVG/图片内容。

### 10.3 余料和跨组补排

Pressria 在一个产品组完成后，会用板材轮廓减去已放轮廓的并集，得到 L 形或更复杂的余料，再把余料视为虚拟板材排下一组。最后还会把此前未放置的产品跨组扫描一次。这个阶段是当前实现下一步需要补齐的核心：

1. 在 Clipper2 中对有效区域做 `difference`，并保留多个余料 polygon；
2. 对每个余料建立面积、包围盒和轮廓类型索引；
3. 先把小图片尝试放入余料，再决定是否开启下一块板材；
4. 所有放置完成后做一次全局 overlap、越界和间距校验；
5. 余料补排不能改变已提交的 DragTransaction，手动调整仍以数据层毫米坐标为准。

这能直接改善“板材还有空白但小图没有补进去”的场景，也能为“最少板材”和“最少切割布局”提供同一块板材上复用轮廓的统计依据。

### 10.4 输出与可追溯性

排版计算只返回 placement，不把低分辨率画布截图当作生产输出。每个 placement 应保留：

```ts
{
  uuid: string,
  sourceId: string,
  qtIndex: number,
  sheetIndex: number,
  xMm: number,
  yMm: number,
  rotationDeg: number,
  contourType: string
}
```

Konva 只负责交互预览和人工微调；SVG 导出使用同一份毫米 placement，并重新引用原始图片或切割路径。这样可以在后续接入白墨、CutContour、注册标和 PDF 合成时保持订单 ID 与切割轮廓一致。

### 10.5 当前边界和实施顺序

Pressria 的 `pressria_tool.exe` 是编译后的 Python 程序，无法仅凭安装包确认 PDF 解析、白墨和最终 PDF 合成的全部细节；本记录只采用可见 JavaScript、第三方声明和运行结构能够证实的部分。推荐按以下顺序继续实现：

1. **策略调度与轮廓缓存**：已完成基础版，继续补充策略命中统计和可重放请求；
2. **余料差集与跨组补排**：使用 Clipper2 生成虚拟板材，复用现有空间索引；
3. **后置压紧和全局校验**：对 NFP、Grid、ironnest、SVGnest 的结果统一复核；
4. **生产输出层**：在 placement SVG 稳定后接入原图、切割线、白墨和 PDF 输出。

评分仍遵循当前约定：先放置数量，再板材数量，再有效区域利用率，再剩余空隙；“最少切割布局”和“综合最少”在这个结果集上统计，不能牺牲间距和碰撞硬约束。
