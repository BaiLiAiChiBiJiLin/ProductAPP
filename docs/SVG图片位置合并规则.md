# SVG 图片位置合并规则

SVG 中多个 `<image>` 可能代表同一张设计图的不同图层。拆分时必须以几何位置和渲染结果为准，不能只比较 `x/y/width/height` 字符串。

## 当前实现

1. 选择包含最多可绘制节点的父级 `<g>` 作为候选图层容器，保留该分组的原始 `transform`。
2. 遍历容器下的直接候选节点。候选节点可以包含 `<image>`、`<path>`、`<line>`、`<polyline>`、`<rect>`、`<circle>`、`<ellipse>`、`<polygon>`、`<text>`、`<use>` 等内容。
3. 为每个候选节点构造临时 SVG，并交给 usvg/resvg 计算实际可见包围盒。这个包围盒已经包含父级变换、描边、裁剪和蒙版产生的可见范围。
4. 含图片的候选节点先按渲染包围盒分组。独立巡边路径和线条不再单独导出，而是计算与每个图片组的矩形间隙、中心距离，挂到最近且相交或处于合理邻近范围的图片组。
5. 每个组内按照原始文档序号重新排列节点，保留原始 XML、`x/y/width/height`、`transform`、`clip-path`、`mask` 和 z-index；不会重新缩放或裁剪节点。
6. 合并前后的候选场景都会由 resvg 以相同尺寸临时渲染，并使用 RGBA 像素差校验。默认阈值为 `0.1%`；校验失败时回退到原始独立候选，宁可多生成图片，也不生成错位或缺少巡边的图片。校验结束后仍保存 SVG，不把合并结果光栅化为 PNG。

## 处理流程

1. 解析每个 `<image>` 的实际变换矩阵，并累乘所有父级 `<g>` 的 `transform`。
2. 将图片四个角转换到 SVG 全局坐标，得到经过旋转、缩放和位移后的几何边界。
3. 解析并应用 `clipPath`、`mask`，计算真实可见区域。
4. 使用 `0.01~0.1` SVG 单位的几何容差判断位置是否相同，不比较原始属性字符串。
5. 合并时保留原始 `x/y/width/height/transform`，不裁剪、不重新缩放图片。
6. 按 SVG 原始文档顺序合成，保持图层 z-index。
7. 使用 resvg 分别渲染合并前和合并后结果，进行像素差校验；超过阈值时放弃合并并保留独立图层。

## 安全原则

- 几何判断只是候选分组，不能直接决定合并。
- 像素差校验失败时宁可多生成图片，也不能生成错位或缺图的图片。
- 外部图片先转换为内嵌数据，再参与几何和像素校验。
- 如果巡边距离所有图片组都超过邻近阈值，则保持独立资源，不强行归属。
