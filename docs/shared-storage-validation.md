# 共享数据方案验证

> 此文记录早期共享文件业务库原型。当前采用“共享目录投递批次包，接收后写入本地数据库”，实现说明见 [shared-batch-transfer.md](shared-batch-transfer.md)，实际业务模块验证见 [shared-transfer-validation.md](shared-transfer-validation.md)。开发使用 `printFlow\dev`，打包后使用 `printFlow\production`；下方旧目录仅保留为已发生测试的记录，不再用于开发测试。

当前按“只有 SMB 共享文件夹访问能力，不在 192.168.0.66 上部署服务”验证。现有 PrintFlow 数据库及业务页面不参与本阶段。

## 已交付的验证工具

- 独立 Rust CLI：`tools/shared-storage-probe`。
- 自动黑盒检查：`tools/shared-storage-probe/verify.py`。
- 两台 Windows 电脑协同入口：`scripts/Test-PrintFlowSharedPair.ps1`。
- 可直接运行的测试包模板与操作说明：`tools/shared-storage-probe/kit`、`tools/shared-storage-probe/README.md`。

正式方案将共享目录作为数据来源。本原型没有本地数据库缓存，每次检查直接读取共享文件，避免被本地缓存掩盖错误。

校验包括正式 JSON 版本连续性、图片文件大小及 SHA-256、审核所有者、生产资源引用、原创建人与生产操作人保留。测试报告在各测试目录的 `verification-report.json`，逐操作结果在 `logs`。

另有 Windows 发布保护测试通过：向已存在的版本路径发布必须失败，原记录字节保持不变。

双机 PowerShell 入口也通过了同机两进程初步检查（共享目录 round 99），并正确显示 SAME computer 警告，未把它误报为双机通过。

测试包：`artifacts/shared-storage-probe-20261014.zip`。同一份展开的工具也在共享测试目录的 `kit` 子目录中，配置指向上述测试根目录。

## 还需要两台电脑执行

复制同一测试包到 A、B 本地，按 README 操作 Setup → A/B → Inspect。初次使用 round 1，重复选择新的相同轮次。该脚本同步两边读取同一版本后提交，不依赖手动同时点按钮。

真实断网测试使用 README 的暂停检查点：A 在 `mid-copy` 或 `after-lock` 暂停时断开到共享目录的连接；B 保持连接检查正式版本并尝试操作。重连后核对提交状态、锁释放、版本冲突与 recover 结果。工具不会自动修改网卡、防火墙或共享服务。

还应测：共享服务器重启、两客户端持续读取期间转移/删除、重复用户注册、同名批次目录、实际历史量下的索引同步/查询、日常大 SVG 保存吞吐量，以及正式三个模块的资源恢复。注册和本地索引尚未实现，不计入本阶段通过项。

## 对结果的解释

当前结果支持继续验证共享文件方案，但尚不能宣布生产可用。两进程使用同一电脑的 SMB 客户端，不能代替两个独立客户端；进程退出/注入失败不能代替网络分区或服务器掉电。

现有 Windows 服务探测脚本 `scripts/Test-PrintFlowService.ps1` 保留备用。把它放在共享目录并在员工电脑启动，仅证明员工电脑运行能力，不代表目标共享机器能运行服务。
