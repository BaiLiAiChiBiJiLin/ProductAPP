# 共享数据方案验证

本阶段验证方案，不修改业务存储。服务探测脚本只提供 GET /health，不读写业务文件或数据库。

## 一、服务能否运行在目标机器

脚本：`scripts/Test-PrintFlowService.ps1`，适用于 Windows PowerShell 5.1 及以上。

必须在 192.168.0.66 对应机器上登录并启动脚本。把脚本放在共享目录，然后在员工电脑运行，进程仍然在员工电脑上，不代表共享机器能运行服务。

在目标机器 PowerShell 中执行（路径按实际放置位置修改）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "C:\PrintFlowTest\Test-PrintFlowService.ps1"
```

保留窗口。从两台员工电脑分别执行：

```powershell
Invoke-RestMethod 'http://192.168.0.66:47822/health' | ConvertTo-Json
```

通过条件：两台都返回相同 probeId、正确 computerName，且 runningOnExpectedHost 为 true。Ctrl+C 停止服务。

结果解释：

- 无法登录目标机器或没有运行程序的权限：当前只有共享目录访问能力，不能据此部署服务。
- 本机可访问，其他电脑不能访问：继续检查网络或入站防火墙；这不等于目标机器不能运行服务。不要为了探测关闭整个防火墙。
- Port already in use：换一个端口重试，启动参数例如 `-Port 47823`，客户端 URL 同步修改。
- runningOnExpectedHost=false：进程在其他电脑上，或预期 IP 不属于它，尚未证明目标机器运行能力。

## 二、共享文件方案的两机验证

需要先实现最小存储验证工具，复用计划用于业务的锁、版本检查、提交及恢复模块。普通复制文件不能证明整个业务方案可用。

测试独立目录：`\\192.168.0.66\电商文件\printFlow\historyProduction\shared-validation\<每次测试的唯一ID>`，不得使用现有 dev/production 业务目录。

电脑 A、B 指向同一测试目录。建立两个测试用户、测试批次、SVG、备注图，以及关联审核/生产记录。工具日志记录操作 ID、用户 ID、电脑、开始结束时间、版本、结果和文件校验值。每轮从共享目录重新读取正式记录校验，本地缓存不作为通过证据。

| 测试 | 操作 | 通过条件 |
| --- | --- | --- |
| 同时保存不同记录 | A、B 同时保存各自批次，重复执行 | 所有成功操作均存在，记录和附件完整，无互相覆盖 |
| 同时保存同一记录 | A、B 读取同版本，用同步开始时间提交不同修改 | 一个提交成功，另一个明确冲突/等待后重新检查版本；不默默覆盖 |
| 写入中断网 | A 保存大附件时中断 A 到共享目录的连接，B 保持连接 | A 不显示假成功；B 只能打开完整已提交版本；恢复连接可重试或恢复 |
| 保存时退出 | 在临时文件写入后、正式提交前、提交后分别强制退出测试工具 | 重启后确认已提交状态或恢复；正式记录无半份内容 |
| 断网后的锁 | A 持锁时断网，B 尝试修改；A 随后重连 | 不出现两个持锁者提交旧版本；锁失效后原客户端必须重新取得锁并校验版本 |
| 用户转移 | A 转移测试批次给 B，逐阶段中断再恢复 | 每条业务记录有唯一所有者；SVG/附件及审核、生产资源都能解析；生产原操作人保留 |
| 转移期间旧页面保存 | B 完成接收后，A 用之前打开的旧版本保存 | 拒绝过期所有权/版本，不把文件写回旧目录 |
| 删除 | 删除测试批次，另一电脑刷新，再尝试旧页面保存 | 文件及记录按删除规则处理，缓存同步删除；旧页面不能复活数据；依赖被删文件的后续流程明确提示缺失 |
| 同名批次与重复注册 | 两机同时创建同名批次、同时注册同一姓名编号 | 批次目录不冲突，用户唯一性得到保证 |
| 正常业务量 | 使用接近日常数量的批次和大 SVG | 测量列表同步、搜索、分页、保存时延及内存，判断是否满足使用要求 |

涉及多记录和文件的更新不能假定共享盘提供数据库事务。验证工具应在各提交阶段支持暂停，以便准确测试断网与恢复。锁和提交行为必须在真实共享目录、两台独立电脑上验证；同一电脑双进程仅作为初步检查。

每项按正常结束、连接中断、进程退出分别复测，并保留日志。即使测试通过，也只能证明该实现与当前共享环境在已测场景下的表现，不能替代备份或代表服务器数据库的事务保证。
