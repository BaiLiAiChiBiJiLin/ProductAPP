# 批次通过共享目录转移

## 使用方式

首次打开软件填写用户名。启动时会在对应环境的共享根目录下注册用户名目录；共享目录暂时不可用时，本地历史仍可使用，可在历史页刷新重试。

| 运行方式 | 共享根目录 |
| --- | --- |
| Tauri 开发运行 | `\\192.168.0.66\电商文件\printFlow\dev\historyProduction` |
| Tauri 打包运行 | `\\192.168.0.66\电商文件\printFlow\production\historyProduction` |

原生端以 `tauri::is_dev()` 选择目录，转移弹窗从原生端读取当前目录。不是根据用户名、前端缓存或手工修改路径决定环境。开发测试不得使用 production 目录。

接收方先打开软件并保存用户名，才会出现在接收用户列表。不同员工应使用不同用户名；相同用户名对应同一个收件目录。

1. 发送方在历史记录页右键批次卡片选择“转移”。
2. 弹窗展示整个批次的图片数量及关联审核、生产拼版数量，选择接收用户后确认。
3. 历史卡片入口直接发送已保存批次，不把整批 SVG 加载到前端。如有未保存的编辑，先保存批次，再返回历史记录页转移。当前版本一次转移整个批次，包括图片属性、分组顺序、备注，以及关联的所有已保存审核和生产记录。
4. 接收方在历史记录页点击“刷新”。收到的记录写入自己的本地 SQLite，资源复制到自己的历史保存目录，路径改为接收方本地路径。
5. 接收完成后，发送方再次刷新历史记录或重启软件，完成原记录和无引用托管文件的清理。

转移不会新增“原操作人”或“生产操作人”字段。任务清单的发送用户仅用于投递和回执校验；现有绘图日期、Designer、产品属性等业务内容照常保留。

## 数据范围与关联

- 批次：批次资料、全部图片资产、真实尺寸、原始像素资料、产品属性、数量、备注、组长与排序。
- 审核：与批次 ID 或图片资产 ID 关联的审核快照、独立画布布局、资源 BLOB、付款状态。
- 生产拼版：关联审核的生产记录、状态、数量、生产图片及配件/备注文件。
- 图片源文件按原字节复制并校验 SHA-256，不重新解析或压缩。审核快照保留自己的原图版本和画布项 ID，独立于当前批次图片。
- 资产、批次、审核及生产记录的数据库 ID 在接收端重新映射；画布项、派生图关系、标尺配置与编组位置保持关联。自定义产品名称映射到接收方本地名称库。

只转移已保存数据；生产页面尚未保存的编辑状态不在包内。若同一资产 ID 被多个历史批次共用，会拒绝单独转移，防止另一批次被同步冻结或误删。不同资产共用同一源文件时，文件按路径去重复制，清理时检查剩余引用。

## 完整性与重试

每次转移有独立任务 ID。网络目录先写 `.pending-任务ID`，文件全部校验通过后才发布为 `task-任务ID`。接收端忽略未发布目录。

数据库保持在各电脑本地。共享包中 `package.sqlite` 是已关闭的交换文件，接收端复制到本地后只读打开；不会把正在使用的 SQLite 放到共享目录并发写入。

接收端在同一本地事务中写入批次、审核、生产记录和接收凭据。所有引用校验通过且事务提交后才写共享回执。反复刷新、接收后重启或回执写入失败后重试，都按任务 ID 去重。

发送期间批次及关联记录暂停修改并从列表隐藏。发送尚未发布就失败，原记录可继续使用；发布结果因断网不确定时保留冻结，刷新验证后继续。旧页面的保存、删除、审核提交和生产数量修改也在数据库事务内检查转移状态。

源数据收到匹配回执后才删除。文件清理只处理应用托管目录中的已交付文件，并检查剩余批次、审核和生产的全部路径引用；不会递归删除文件夹或删除桌面上的导出文件。锁定文件清理失败会保留候选，在下次刷新重试。

共享包与发送暂存目前保留用于回执恢复和排查，不自动定期删除。单个文件上限 512 MB、单条 JSON 记录上限 64 MB、每包文件上限 10,000、总文件大小上限 12 GiB；超限在发布前拒绝，不会锁死原批次。
