# 本地拼版 Rust 搜索核心与性能验收（2026-10-13）

目录整理补记：运行源码现统一位于 `src-tauri/src/imposition/local_nesting/`。下文性能数值为迁移搜索核心时的历史测量；其中 `.test-output/` 临时证据已按清理要求移除。当前目录迁移的回归结果见 [本地拼版运行说明](../scripts/nesting/README.md#2026-10-13-目录迁移验收)，不能将本次目录整理解读为重新取得下文整批性能数据。

## 范围

两种本地策略仍共用同一个单板搜索接口。Python 保留 Shapely 轮廓准备、旋转掩码缓存、随机排序、数量配额、模板复用和最终真实几何校验；Rust 接管整个单板放置循环、候选位置扫描、位图碰撞、占用更新和搜索起点缓存。

未减少角度（0–345°，每 15°）、未放宽 3 mm 间距，基准均使用 0.5 mm 栅格。图片像素和 SVG 内嵌 image 不进入搜索。

## Rust 核心和稳定性

- 独立零依赖 `cdylib`，以 release 编译，不依赖 Tauri 的 dev/release 配置。
- 一个基础旋转掩码只上传一次，压缩成 `u64` 位图，多个 QT 及多个试排共享。Python 原掩码保留以支持对照和回退，不把位图压缩比例等同于整个进程内存降幅。
- 根据碰撞像素对应的连续占用段，跳过确定不可能合法的位置；结果仍为原算法逐行从左到右找到的第一个合法位置。
- 默认 2 个搜索线程（包含调用线程），最多 4 个；按原角度索引归并结果，评分相同仍保留原有优先顺序。每次单板计算只创建一组线程，所有角度共享占用位图和掩码。
- Windows 可用物理内存与提交内存取较小值；不足 768 MiB 时降到 1 线程。分配预算预留 256 MiB；Rust 使用可失败分配并检查数组、边界和预算，线程创建失败降低并行数。
- 数量和结果只在整块板计算成功后提交；可恢复的原生错误按原参数重算该板，随后使用 Python。前端结果明确标注 Rust、Python 或混合回退，基准不能把回退记成 Rust 提速。
- C ABI 捕获 Rust panic；绑定层防止活跃计算期间释放或重入句柄。整个求解仍在独立 Python 适配进程中，不把原生库直接加载进桌面 UI 进程。

这些防护减少已知风险，不能保证操作系统耗尽资源、原生内存损坏等情况永不发生。

## 对照方法

固定同一份毫米请求、QT、随机种子、排序/评分、角度、间距、栅格与缓存模式。对每个副本比较来源、板号、位置、旋转角度以及需求数量；另用真实多边形验证重叠、间距和完整图片框边界。最终完整 SVG 切割模板计数还需读取原始 SVG，包括内孔，不能只靠协议中的外轮廓判定。

8 × 20 初测：Python 25.7317 秒，Rust 2 线程 1.2723 秒；160 张、3 板、3 种外轮廓版式及所有放置位置的签名完全一致。此次 Rust 短测试期间完整 Python 基线在后台运行，只作为先期检查，最终提速以单独顺序运行的整批对照为准。

### 独立整批计时

两边均关闭 cProfile，使用已验证的完整热缓存和相同的轻量调用计时包装。所有缓存文件的名称、大小、修改时间在运行前后不变；基础掩码均为 2016 个、53,441,972 字节，栅格均为 0.5 mm。比较脚本对输入、配置、缓存、计时范围、实际后端和质量检查均通过后才计算倍数。

| 策略 | Python 求解 | Rust 求解（2 线程） | 提速 | Python / Rust 搜索阶段 |

| 节省板材 | 1119.002 秒 | 9.365 秒 | 119.48 倍 | 1115.404 / 5.727 秒 |
| 切割方案优先 | 430.819 秒 | 4.238 秒 | 101.66 倍 | 429.641 / 3.014 秒 |

### 有限并行档位对照

对同一 84 种 / 1005 个数量的节省板材请求，顺序测量 1、2、4 线程。三者均通过独立几何检查，且全部放置与 Python 参考逐项相同。

| 搜索线程数（含调用线程） | 求解耗时 | 其中搜索耗时 | 求解进程峰值提交内存 |
| --- | --- | --- | --- |
| 1 | 12.577 秒 | 8.978 秒 | 140.770 MiB |
| 2（默认） | 9.365 秒 | 5.727 秒 | 140.313 MiB |
| 4 | 7.443 秒 | 3.885 秒 | 140.633 MiB |

保留默认 2 线程以给桌面其他工作留出 CPU；可通过环境变量选择 4 线程，低内存保护仍生效。峰值的微小差异属于整个进程的运行波动，不能据此推断 2 线程比 1 线程省内存。

证据：`.test-output/local-tools/rust-migration-thread-comparison.json` 及相邻 `rust-migration-rust-material-84x1005-threads-1`、`threads-4` 下的完整报告。

### 整批结果一致性

84 种真实 SVG、1005 个测试数量的两种策略均已通过独立几何验证，Rust 与先前完成的 Python 基准逐项比较 `placements` 和 `excludedItems` 完全相同：

| 策略 | 放入数量 | 板材数 | 完整 SVG 切割版式数 | 坐标和旋转 |
| --- | --- | --- | --- | --- |
| 节省板材 | 1005 / 1005 | 33 | 31 | 全部相同 |
| 切割方案优先 | 1005 / 1005 | 34 | 10 | 全部相同 |

完整 SVG 版式数来自原基准对原始 SVG 内外切割线的校验；本次固定请求和每一条放置数据均未变。新性能脚本独立计算的是请求外轮廓版式数，在此数据上同样得到 31 / 10，不将它冒充所有输入都适用的完整切割线分析。

最终对照前的首轮整批 Rust 求解耗时分别为 9.695 秒、3.727 秒，也得到相同结果。两轮均使用 2 线程，上传 2016 个基础旋转掩码，Rust 掩码库约 8.75 MiB，且没有回退到 Python。计时仅含适配器求解，完整进程另有启动开销；不含桌面端 SVG 读取、输入轮廓提取和 Konva 绘制。

## 构建、选择和复现

本轮主要改动文件：

- `src-tauri/src/imposition/local_nesting/rust_core/`：独立 Rust 位图搜索核心、C ABI、单元测试与接口说明。
- `src-tauri/src/imposition/local_nesting/nesting_rust.py`：Python 绑定、上下文复用、线程和内存保护、原算法回退。
- `src-tauri/src/imposition/local_nesting/nesting_common.py`：保留 `_pack_one_python`，共用入口分派到所选核心。
- `src-tauri/src/imposition/local_nesting/local_tools_engine.py`：两种策略共享掩码库，结果报告实际核心与回退原因。
- `scripts/nesting/build_rust_core.ps1`、`setup_local_tools.ps1`：构建、部署与 Python-only 安装选项。
- `scripts/nesting/profile_local_tools.py`：同输入剖析、峰值内存、质量差分与可比性保护。
- `scripts/nesting/test_rust_nesting_core.py`、`test_local_tools_engine.py`：绑定和适配器回归。
- `scripts/nesting/README.md` 及本文：使用方法和实测记录。

```powershell
# 安装 Python 依赖并构建部署 Rust 搜索核心
powershell -File scripts/nesting/setup_local_tools.ps1
# 只编译候选库，不替换正式库
powershell -File scripts/nesting/build_rust_core.ps1 -SkipDeploy
# 默认 auto：可用时使用 Rust；缺库时明确回退 Python
$env:PRINTFLOW_NESTING_CORE = 'auto'
# 强制 Python 作参考
$env:PRINTFLOW_NESTING_CORE = 'python'
# 强制 Rust 作性能验证，缺库明确报错
$env:PRINTFLOW_NESTING_CORE = 'rust'
$env:PRINTFLOW_NESTING_THREADS = '2'
$env:PRINTFLOW_NESTING_CORE_LIBRARY = (Resolve-Path .tools/nesting/rust-core-target/release/printflow_nesting_core.dll).Path
```

切换环境变量作用于新启动的求解进程。`setup_local_tools.ps1 -PythonOnly` 可只安装 Python 参考运行时。
