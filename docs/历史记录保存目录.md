# 历史记录保存目录与批次文件夹

入口：右上角用户信息 → 设置。设置是独立的 Ant Design 弹窗，支持输入完整目录、系统文件夹选择器、恢复默认。点击保存后生效；取消不修改设置。不可写的目录显示错误并保留弹窗。

## 文件和数据库

- 临时导入：`printflow-data/temp-assets/资源ID.svg`。
- 新保存的批次：`历史记录保存目录/客户名称_年月日时分/资源ID.svg`。
- 默认历史记录保存目录：软件目录下的 `printflow-data/assets`；开发环境位于项目目录。发行版使用可执行文件所在目录，不依赖快捷方式的工作目录。
- 使用首次保存的系统本地时间，例如 `客户甲_202610091016`。同一分钟同名批次继续编号，例如 `客户甲_202610091016 (2)`。Windows 不允许的文件名字符会替换，空名称使用“未命名批次”。
- 已有文件夹不强制改名，保证旧路径有效。文件夹首次分配后与批次 ID 绑定。修改属性、客户名称、默认目录后，再次保存同一批次仍使用已分配的位置，不复制成新的历史记录。
- 设置和批次目录映射由 Rust 写入原来的 SQLite 数据库：`app_settings`、`batch_asset_directories`。每张图片的 `storagePath` 继续记录完整绝对路径。数据库仍位于应用数据目录，修改本设置不会迁移数据库。

## 修改目录与旧数据兼容

目录设置只影响尚未分配保存文件夹的批次，不自动搬迁已有历史文件。旧版本在 `printflow-data/assets` 平铺保存的 SVG 仍按原路径读取；这类批次再次保存时会建立批次文件夹并更新当前记录的路径，旧原文件保留，避免破坏已经生成的生产记录引用。

已分配目录的历史批次继续在原处打开、编辑和保存。生产拼版识别数据库登记的批次目录，不再要求图片必须直接位于 `printflow-data/assets`。

历史批次保留删除入口。`delete_batch` 删除批次记录与预览缓存，并清理未被其他批次或已有生产任务引用的资源记录、SVG 文件及空批次目录。审核记录本身不阻止删除：审核虽然有独立 SVG 快照，后续进入拼版仍需要原批次文件；用户明确接受源文件删除后后续流程不可继续的行为，此时显示“已保存批次文件不存在”。不自动恢复被用户主动删除的文件。

## 原始内容与保存顺序

Rust 逐张复制 SVG 原始字节，不重新解析、栅格化、压缩嵌入图片或修改宽高。真实尺寸、原始图片像素/毫米信息、产品属性、备注和组合顺序保持原值。

先写入批次 SVG，再提交数据库中的图片和批次路径，提交成功后仅清理本次保存涉及的临时 SVG。失败时保留临时源文件，允许重试，不清空其他正在导入批次的临时文件。前端只传路径和属性时直接复制文件，避免把整批 SVG 再次读入内存。

## 模块与验证

- `src/modules/settings/`：设置弹窗、目录选择、IPC。
- `src-tauri/src/settings.rs`：异步 Tauri 设置命令。
- `src-tauri/src/asset_storage.rs`：设置、目录分配、原文件保存与安全清理。
- `cargo test --example verify_asset_storage`：隔离临时文件与 SQLite，覆盖目录设置持久化、同名批次、失败重试、旧/新目录历史读取、SVG/属性不变、临时文件清理，以及删除已有关联审核的历史批次后记录/文件/目录/缓存清理、后续生产明确报告缺失源文件。
- `npx vitest run tests/storage-settings.test.tsx`：弹窗加载、目录选择、取消、恢复默认、错误提示和重复点击保护。

Windows 环境下完整 `cargo test --lib` 测试程序曾在启动时返回 `0xc0000139`；独立 example 测试直接复用上述业务模块，避免访问用户数据库，也不依赖完整原生应用启动。

## 历史记录分页与搜索

“最近使用记录”卡片区提供批次名、单个保存日期和重置，不再显示搜索按钮或“最近使用批次”小标题。名称停止输入 400 毫秒后自动筛选；中文输入法选字期间暂停，选字结束后重新计时。名称框按回车立即搜索，日期选择或清空立即和当前名称一起筛选，条件变化后回到第一页。重置同时清空名称、日期和待执行查询；相同条件不重复查询，也不覆盖用户随后切换的页码。

底部固定分页器，默认每页 12 个，可切换 24 / 48 个。卡片内容区内部滚动，不挤出底部分页器。打开批次加载图片时隐藏搜索区、卡片和分页器，只显示加载动画与进度，并取消待执行的自动搜索；返回列表会保留筛选并刷新。启动时只展示历史卡片，不自动打开历史批次。

`batch_history::list` 在 SQLite 执行名称匹配、日期条件、COUNT、LIMIT/OFFSET，不再限制总记录数为 20 条。名字使用字面子串匹配，`%` / `_` 不被视为通配符。所选日期按用户当地日期转换成带时区的时间，包含当天零点至下一天零点之前的所有记录。

列表响应只包含 ID、名称、保存时间、图片数量，不返回图片数组、SVG、备注图片等大字段。卡片恢复前四张图片的缩略图：可见卡片按队列逐个请求 `load_batch_thumbnails`，Rust 在后台逐张渲染最长边 128px 的小预览，并缓存到 SQLite 的 `batch_thumbnail_cache` 表。文件路径、大小、修改时间、顺序变化会更新缓存；旧内联 SVG 使用批次保存时间判断更新。单张失败显示预览占位，不阻止打开批次。翻页或打开批次时取消尚未开始的预览请求。

这些小 PNG 仅用于历史卡片预览，不覆盖、压缩或修改任何原始 SVG、嵌入图片、真实尺寸和产品属性。真正打开批次后仍按原有逐张加载流程读取完整 SVG。删除历史批次时清理预览缓存；删除最后一页的最后记录时，后端自动回退到最后一个有效页。

页面交互封装在 `src/modules/schematic/history/BatchHistoryPanel.tsx`，自动搜索与输入法状态独立放在 `useBatchHistoryFilters.ts`。回归测试：`tests/batch-history-panel.test.tsx`、`tests/batch-history-filters.test.ts`；Rust 测试继续运行 `cargo test --example verify_asset_storage`。
